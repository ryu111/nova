# 06 IHarness 要補什麼

[`04-載體要長什麼樣.md`](04-載體要長什麼樣.md) 回答「IHarness 有哪幾個面、
為什麼現在不寫 `class IHarness(Protocol)`」。這一份接下去回答**可執行的那半**：
每個面**還缺什麼、缺的東西長什麼形狀、先做哪個**。

## 材料：三份分類擺在一起

sharktech〈什麼是 harness engineering〉列的六項（2026-08-29 對原文逐字核過）：

> - 工具管理：Agent 可以使用哪些工具、如何調用
> - 狀態持久化：跨越多個上下文視窗的記憶與進度追蹤
> - 環境約束：沙盒、權限邊界、安全防護
> - 反饋迴路：驗證輸出、偵測錯誤、觸發修正
> - 多 Agent 協作：任務分解、Agent 間的交接機制
> - 可觀測性：日誌、監控、人工審查介入點

規格 §2.1 的六大：Context 注入／行動面／持久化／執行控制／安全與治理／可觀測性。

**兩份不是同一種切法**，對照的細節（誰多了什麼、誰把同一件事放在別格）寫在 04，
這裡不重複。這份只用一個結論：**兩邊合起來蓋得住的範圍，就是 IHarness 的邊界**；
`nova` 的落點以規格為準，sharktech 的用處是**補出規格沒明講的子項**。

## 六個面各自缺什麼

「缺」的判準是**指得出檔案或指得出沒有檔案**，不是感覺不足。

### ① Context 注入 — 缺「目標專案的規範」

| | |
|---|---|
| 現況 | `src/nova/迴圈/角色提示.py` 三段固定系統提示；`src/nova/迴圈/工作流.py` 的 `_提示` 併上一步證據 |
| 缺什麼 | 那三段**寫死了 nova 自己的規矩**（繁體中文命名、測試放 `tests/`）。而 `隔離設定` 預設關掉目標 repo 的規範來源，**沒有接縫把它讀回來** |
| 形狀 | `任務` 多一個「專案規範」欄位，由 CLI 從工作目錄讀（`AGENTS.md`／`CLAUDE.md`），讀不到就**留白**——不要硬塞 nova 的規矩 |
| 缺在 | 迴圈 |

為什麼這條排第一：它是**唯一會產生「看起來完全正常的錯」**的缺口。
模型照規矩做了，只是照錯專案的規矩，輸出挑不出毛病。

### ② 行動面 — 網路補上了，剩下的夠用

三家轉接器、工具白名單、接力鏈都在。sharktech 的「工具管理」對應這一格，
它多講的「如何調用」在 `02` 已經逐旗標記過。

**2026-08-29 補：網路原本是缺的，而且缺得很隱蔽**——三家都上不了網，
但理由各不相同，所以「委派出去做研究」這件事根本做不了：

| 家 | 為什麼上不了網 | 修法 | 代價 |
|---|---|---|---|
| codex | `--sandbox workspace-write` 連網路一起關（`curl` 回 `000`） | `-c sandbox_workspace_write.network_access=true` | **沒有**——檔案沙箱照樣在 |
| agy | `read_url` 被 headless 權限系統 auto-deny | `--dangerously-skip-permissions` | **失去唯一的越界保護** |

agy 那個代價是被逼的：`agy --help` 查證過，它**沒有工具白名單旗標、
沒有 settings 路徑旗標**，唯一的開關就是那條。開網路就是開全部。
使用者裁定接受，由 `test_agy的可編輯沒有邊界這是已知事實_換網路換來的`（手動跑）誠實釘住。
**要邊界就用 codex。**

### ③ 持久化 — 熔斷已接線，但預設關閉；checkpoint 仍然沒有

| | |
|---|---|
| 現況 | `src/nova/載體/帳本.py` 寫、`src/nova/載體/帳本讀取.py` 讀；`src/nova/載體/熔斷.py` 的 `該跳過嗎` 經 `src/nova/載體/命令列.py` 的 `_這個專案誰熔斷了` 與 `_濾掉熔斷的` 接進 `nova 問` 的接力鏈；**進度檔**（`src/nova/載體/進度.py`）讓下一輪接得上 |
| 缺什麼 | **checkpoint 仍然沒有**；跨執行熔斷雖已接線，但預設被旗標鎖住，明講 `nova 問 --熔斷` 才啟用，所以預設實際上不影響行為 |
| 形狀 | `該跳過嗎` 只讀最近 10 次執行；同一家連續失敗 3 次進入熔斷，冷卻 30 分鐘；「未知」既不推進計數也不歸零；讀不到帳本時 fail-open 不熔斷；明講 `nova 問 --熔斷` 時，接力鏈會濾掉熔斷的家 |
| 缺在 | 載體 |

**進度檔為什麼不能靠帳本**：帳本記的全文是遮過的（有洞）而且超過上限會截斷，
所以它答得出「停在哪一階」，答不出「它當時做了什麼」。下一輪要接得上，
需要的正好是後者。兩個都要，而且不重複。

sharktech 把這格叫「跨越多個上下文視窗的記憶與進度追蹤」。**「跨越」是關鍵字**：
nova 的帳本仍是一個執行一個檔；熔斷會讀最近 10 次執行，所以跨執行影響行為的路徑已存在，
但預設關閉；checkpoint 仍然沒有。

### ④ 執行控制 — 缺「審批閘」

| | |
|---|---|
| 現況 | 逾時、停止條件（步數＋token）、模型路由、回頭邊 |
| 缺什麼 | 規格 §2.1 明列的**審批閘**。`src/nova/契約/工作流.py` 的 `種類` 只有 `模型／判準／審查`，**沒有人類節點可以住的位置** |
| 形狀 | `種類` 多一個值，狀態機走到它就停下等外部輸入；帳本記「等了多久、誰放行的」 |
| 缺在 | 迴圈（型別）＋載體（怎麼問人） |

### ⑤ 安全與治理 — 缺「人工簽核」

| | |
|---|---|
| 現況 | 三級權限、三家沙箱、`禁令.py`、機密不進版控。這格挖得最深 |
| 缺什麼 | 規格明列的**人工簽核**。`--全開` 一路走到各家的 `dangerously-*` 旗標，中間沒有確認點 |
| 形狀 | 權限升到全開時要一個外部確認；非互動情境要能用「事先簽好的授權」代替，否則 CI 會卡死 |
| 缺在 | 載體 |

sharktech 這格叫「環境約束」，內容一致。

### ⑥ 可觀測性 — 缺「遮罩」與「感測器歷史」

| | |
|---|---|
| 現況 | `載體/模型/記帳.py` 記模型呼叫、`載體/階段記帳.py` 記階段 |
| 缺什麼 | **不記全文是靠「不記」不是靠遮罩**，所以帳本永遠答不出「它說了什麼」。（閘的觸發率已補：`載體/閘.py` 現在每條規則記一對事件） |
| 形狀 | 遮罩：白名單結構欄位＋雜湊，另案。感測器歷史：閘每跑一條就記一筆 |
| 缺在 | 載體 |

sharktech 把「人工審查介入點」也放在這格（規格放在⑤）。引用時要指名是誰的分類。

## 先做哪個：規則觸發率

Fowler 的〈sensors〉問了一句 04 一度以為沒人回答得了的話——她後來自己答了，逐字：

> "So I started **logging a history of sensor states every time they were checked**,
> to get some data."

而且列出這份歷史回答得了什麼（逐字轉述）：失敗頻率的趨勢是**指引或模型在進步**的訊號；
**從來不失敗的感測器**是「它不必要」的訊號；**常失敗的規則**是「該補指引」的訊號。

這條對 nova 特別便宜，因為零件都在了：帳本會寫、階段記帳已經在記判準紅綠、
讀取端有 `收斂`。**缺的只有一格——`src/nova/載體/閘.py` 不寫帳本。**

補上之後同時解掉兩個面：

```
⑥ 可觀測性  ← 規則觸發率有資料了
③ 持久化    ← 「長期觸發率為零的規則是刪除候選」＝第一個因為帳本而改變的決定
```

**那就是 Evidence 變成 State 的第一步**，而且它不需要新概念，只要接一條線。

## Loop 的四步各自缺什麼

`harness[loop[llm]]` 的中括號是包含關係，所以這份文件只盤點外層是不夠的。
loop engineering 的四步（行動 → 觀察 → 推理 → 重複）對 nova 的落點：

```
行動  執行一步 → 角色.做() → CLI        src/nova/迴圈/工作流.py
觀察  步驟結果（階段／終局／判準綠／證據／審查結論／花費）＋ 機械判準
推理  下一步() 純函式轉移表              src/nova/迴圈/狀態機.py
重複  跑工作流 的 for + 停止條件
```

原本最弱的是「推理」：`下一步` 只認「綠／紅／結果未知／確定失敗」四種，
**不認失敗的種類**——額度用完、逾時、權限被擋、模型真的做不到，四件事走同一條邊。

### 已經補上的四格

| 步 | 補了什麼 | 為什麼那是同一條鏈 |
|---|---|---|
| 觀察 | stderr 不准被 nova 自己的罐頭句吞掉（`載體/模型/解析.py`） | 拿不到失敗原因，推理就沒東西可推 |
| 推理 | `卡住了()`：同一個判準吐出一模一樣的紅 3 次就停 | 這是「重複相同失敗方法」那條反模式的機械形式 |
| 推理 | `permission-denied`／`quota-exhausted` 從 `unknown` 拆出來 | **兩者的處置相反**：額度用完換腦、權限被擋換腦沒用 |
| 重複 | `結束代碼.護欄` 與退出碼 4 | 外圈分得出「按設計停了」與「壞了」，才不會把上限調高當成修好 |

觀察那格的 bug 值得記住形狀：`_成功但沒話說算未知` 先把 `文字` 填成罐頭句，
`_補上診斷` 的守衛 `if 答.文字.strip()` 就以為「已經有話說了」。
**填充值會偽裝成真值**——這種洞不會紅、不會拋例外，只是永遠答不出「為什麼」。

### 端到端證據：七階段真的跑完過

盤點做到這裡為止都是「每一段測過」，**整條沒有證據**。2026-08-29 補上了：

```
退出碼 0（完成）· agy×3、codex×1 · 527,545 token（預算 800k）

test            success
verify-red      success  綠=False   ← 真的看到它紅
impl            success
verify-green    success  綠=True
refactor        success
verify-refactor success  綠=True
review          success             ← REVIEW: PASS
```

題目是「把 `add` 改名成 `相加`」，檔案真的被改、測試真的跟著改。
**派工表也在同一次證實了**：三個例行階段走 agy、審查走 codex。

觀察那格的 bug 值得記住形狀：`_成功但沒話說算未知` 先把 `文字` 填成罐頭句，
`_補上診斷` 的守衛 `if 答.文字.strip()` 就以為「已經有話說了」。
**填充值會偽裝成真值**——這種洞不會紅、不會拋例外，只是永遠答不出「為什麼」。

### 還缺的：失敗分類 → 換策略

`卡住了` 只做到「停得早一點」。真正的推理是**依失敗種類走不同的邊**。
下面這張表是委派研究（agy 查業界做法、codex 查停止條件、sol-max 濃縮）之後，
**只留下 nova 現有訊號判得出來、而且不違反 at-most-once 的那幾條**：

| 失敗種類 | 訊號（nova 現在有沒有） | 該轉去哪 | 為什麼不能一律停 |
|---|---|---|---|
| 判準沒達標 | ✅ `判準綠=False` | 退回上一個產出那個東西的階段 | 紅燈是可操作的回饋，正是回頭邊在做的事 |
| 腦不可用（`model-not-found`／`not-installed`） | ✅ `失敗代碼` | 換腦 | **已經有了**——`載體/模型/接力.py` |
| 認證／用法錯誤（`auth`／`usage`） | ✅ `失敗代碼` | 等人 | 同參數重跑不會補出憑證 |
| 逾時（`timeout`） | ✅ `失敗代碼` | 可編輯：停。唯讀：縮小題目 | 唯讀沒有副作用，縮範圍比白白終止合理 |
| 額度耗盡 | ✅ `quota-exhausted`（**三家的字串都查證過**） | **換腦**——額度綁在 provider 上 | 等人是錯的：換一家就好，這正是接力鏈存在的理由 |
| 權限被擋 | ✅ `permission-denied` | 等人，而且**不准換腦** | 下一顆撞同一堵牆，換三顆就白燒三次 |
| Context 單次上限 | ❌ 沒有對應的失敗代碼 | 縮小題目 | 這是輸入太大，不是解題失敗 |

**這兩條做完了。** 都靠 stderr 的固定字串規則命中，而 stderr 是上一個 PR 才剛拿得到的
——這就是「觀察補完，推理才有東西可推」的具體樣子（1+1>2 的那個 1）。

**兩條的處置方向相反**，這正是「不分類就只能一律停」的代價：

```
額度耗盡  → 換腦（額度綁在 provider 上，換一家就好）
權限被擋  → 不准換腦（沙箱與旗標是 nova 自己組的，對整條鏈都一樣）
```

補之前，兩種都是 `unknown`／`結果未知`，於是**一條 `--用 codex,agy` 的鏈
在最該換手的時候不換**，而在換了也沒用的時候照樣把剩下的腦全燒一遍。

額度那條的字串現在**三家都有出處**（codex issue #38603、claude issue #86272
＋官方 Errors 文件、antigravity issue #789）。過程留下一條規矩：

**變體會長出來的東西不准寫死。** claude 的額度訊息是
`You've hit your <session|weekly|Opus|Sonnet> limit`——中間那個字是方案期間或型號名。
寫死四個，出第五個型號就**靜默失效**，而靜默失效的分類器比沒有更糟。
所以那一組是樣式 `hit your \w+ limit` 不是字串。
由 `test_還沒出現的型號名也要命中` 背書——**寫死四個的話那支會紅，其他四支照樣綠。**

**下一條：`context-exhausted`。** 缺的還是字串證據。同一份研究逐條標了
「stdout 還是 stderr 查不到」，也警告過不要拿 Gemini CLI 的
`Resource exhausted` 冒充 agy 的輸出——**那條帶著 `Retrying after 1s`，
是暫時容量問題不是額度用完**，判錯會讓接力白換一家。

**不做的**：不准叫模型讀 stderr 自己判斷這是什麼錯。
轉移必須是純函式判得出來的，否則測試就要付 token，而且判準會隨模型漂移。

## 六個面沒問的一句話：載體自己的狀態，執行者摸不摸得到

**這不是第七個面。** 六個面是規格 §2.1 的，而且對過五篇原文驗過沒漏——
隨便加一格會推翻那個結論。這是一條**橫切六個面的判準**，而盤點的時候沒問。

問題是真的跑出來的（2026-08-29，跑完整七階段那次）：進度檔放在工作目錄裡，
**模型讀了它、照抄格式、接了一段自己的話上去**。同一階段同一題目，只差位置：

```
進度檔在工作目錄裡 → nova 寫的段落數 2      進度檔在工作目錄外 → 1
```

為什麼這一格特別要緊：進度檔下一輪會被當成 `前情` 餵回模型。
**執行者可以在載體的記憶裡種話給未來的自己看。**
宿主反轉的整句是「保證住在包住執行者的程式碼裡」——連狀態都住在裡面就沒有殼了。

### 把這條判準套在 nova 自己身上

| 載體的狀態 | 住在哪 | 工作目錄是別人的專案 | **工作目錄就是 nova 自己** |
|---|---|---|---|
| 帳本 | `~/.local/state/nova/帳本/` | 摸不到 | 摸不到 |
| 進度檔 | 呼叫端指定 | **已擋**（`檢查進度檔位置`） | 已擋 |
| 規則表、禁令、角色提示 | repo 原始碼 | 摸不到 | **摸得到** |
| 測試（唯一的驗收介面） | repo | 摸不到 | **摸得到** |
| GitHub 的 required check | GitHub 設定，不是檔案 | 摸不到 | 摸不到 |

**最後一列是真正的底線。** 前面兩列「摸得到」是真的：這個 repo 本來就會叫模型
重構 nova 自己（PR #53 就是 codex 產的）。模型可以同時弱化 `規則表.py`
與守它的 `test_閘的條數要跟規則表一致`，兩邊一起改就沒有機械把關抓得到。

擋下來的是**人看 PR diff**，以及 GitHub 那條 `gates` required check
（它是設定不是檔案，模型改不到）——但那條只保證「閘有跑」，
不保證「閘裡還有幾條規則」。

**這一格現在沒有機械保證，而且誠實地說：短期也不會有。**
候選解是「規則表的指紋比對，基準存在 repo 外面」，但那要有一個
模型碰不到的地方存基準——現在沒有。**寫在這裡是為了不要有人以為它被守著。**

## 現在哪些是殼、哪些還不是

（這張表本來住在 `CLAUDE.md`。它是**盤點**不是規則，而盤點會一直變——
規則檔裡的盤點遲早跟事實對不上，所以搬到這裡。）

它就在模型手上。

`nova 問` 不是走錯路：它是「執行核」第 ② 步的雛形，缺的是包住它的 ①③④——
**出生前就擋**（秘密、預算鎖、熔斷）、**它說的話唯一的出路是 journal**、**終態分類**。
預算鎖在**工作流**那一層已經有了（`src/nova/契約/工作流.py` 的 `停止條件`）；
`nova 問` 這條單次呼叫的路徑**還沒有**——它一次只發一個請求，沒有累計的對象。

「它說的話唯一的出路是 journal」現在有了：`src/nova/載體/帳本.py` 寫、

**帳本影響行為的路徑已存在（熔斷是第一條）**，但**預設被旗標鎖住**，
明講 `nova 問 --熔斷` 才啟用；細節見上面的 ③ 持久化那一格。

所以它回答得了「誰被叫了、花多少、怎麼收場」，回答不了「它說了什麼」。

## 什麼時候才寫 `class IHarness(Protocol)`

04 的結論不變（**現在不寫**），但這份文件讓那個條件變得可檢查：

> 出現**第二個載體實作**的那天才寫。在那之前，這六個面是**盤點用的分類**，
> 不是型別。

可檢查的判準：上面六格裡，有任何一格出現「兩種做法要在執行期互換」時，
那一格先抽成一個小 `Protocol`——**不是六個面一起抽成一個大介面**
（介面隔離：一個大 `Protocol` 會逼所有人實作用不到的方法）。

## 這份文件自己的限制

- 六格的「缺什麼」全部對 code 查證過（指得出檔案或指得出沒有檔案）；
  **「形狀」那一欄是提案，沒有實作也沒有測試背書**。
- **「失敗分類 → 換策略」那張表同理**：它是委派研究濃縮出來的，
  ✅ 那幾格對 code 查證過，❌ 那幾格是「現在判不出來」的查證結果，
  但「該轉去哪」整欄**還沒有任何測試背書**。
- **「載體自己的狀態，執行者摸不摸得到」那節只有一格有機械保證**（進度檔）。
  規則表與測試那兩格明寫著沒有，而且短期不會有——寫在那裡就是為了不要有人
  以為它被守著（宣稱有把關卻沒有，比沒有規範更糟）。
- 委派來的建議查證過一次就抓到一條假的：sol-max 推薦「先做腦不可用 → 換腦」，
  而 `載體/模型/接力.py` 已經有了，**而且比提案更嚴謹**（它按權限決定能不能換，
  可編輯 ＋ 結果未知 就不換，守住 at-most-once）。**委派來的東西不能直接採信。**
- sharktech 與 Fowler 的引用是 2026-08-29 對原文逐字核過的，
  不是二手轉述——但**原文本身的可信度**（sharktech 是二手整理）由 04 的材料表管。
