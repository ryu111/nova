# 06 IHarness 要補什麼

[`04-載體要長什麼樣.md`](04-載體要長什麼樣.md) 回答「IHarness 有哪幾個面、
為什麼現在不寫 `class IHarness(Protocol)`」。這一份接下去回答**可執行的那半**：
每個面**還缺什麼、缺的東西長什麼形狀、先做哪個**。

## 材料：三份分類擺在一起

sharktech〈什麼是 harness engineering〉列的六項（2026-08-29 對原文逐字核過）：

> - 工具管理：Agent 可以使用哪些工具、如何調用
> - 狀態持久化：跨越多個上下文視窗的記憶與進度追蹤
> - 環境約束：沙盒、權限邊界、安全防護
> - 反饋迴路：驗證輸出、偵測錯誤、觸發修正
> - 多 Agent 協作：任務分解、Agent 間的交接機制
> - 可觀測性：日誌、監控、人工審查介入點

規格 §2.1 的六大：Context 注入／行動面／持久化／執行控制／安全與治理／可觀測性。

**兩份不是同一種切法**，對照的細節（誰多了什麼、誰把同一件事放在別格）寫在 04，
這裡不重複。這份只用一個結論：**兩邊合起來蓋得住的範圍，就是 IHarness 的邊界**；
`nova` 的落點以規格為準，sharktech 的用處是**補出規格沒明講的子項**。

## 六個面各自缺什麼

「缺」的判準是**指得出檔案或指得出沒有檔案**，不是感覺不足。

### ① Context 注入 — 缺「目標專案的規範」

| | |
|---|---|
| 現況 | `src/nova/迴圈/角色提示.py` 三段固定系統提示；`src/nova/迴圈/工作流.py` 的 `_提示` 併上一步證據 |
| 缺什麼 | 那三段**寫死了 nova 自己的規矩**（繁體中文命名、測試放 `tests/`）。而 `隔離設定` 預設關掉目標 repo 的規範來源，**沒有接縫把它讀回來** |
| 形狀 | `任務` 多一個「專案規範」欄位，由 CLI 從工作目錄讀（`AGENTS.md`／`CLAUDE.md`），讀不到就**留白**——不要硬塞 nova 的規矩 |
| 缺在 | 迴圈 |

為什麼這條排第一：它是**唯一會產生「看起來完全正常的錯」**的缺口。
模型照規矩做了，只是照錯專案的規矩，輸出挑不出毛病。

### ② 行動面 — 夠用

三家轉接器、工具白名單、接力鏈都在。sharktech 的「工具管理」對應這一格，
它多講的「如何調用」在 `02` 已經逐旗標記過。

### ③ 持久化 — 缺「有人依它決策」

| | |
|---|---|
| 現況 | `src/nova/載體/帳本.py` 寫、`src/nova/載體/帳本讀取.py` 讀 |
| 缺什麼 | **沒有任何一行程式碼會因為帳本裡的東西改變行為。** 這是 Evidence 與 State 的分界 |
| 形狀 | 見下面「先做哪個」——第一個呼叫端是規則觸發率 |
| 缺在 | 載體 |

sharktech 把這格叫「跨越多個上下文視窗的記憶與進度追蹤」。**「跨越」是關鍵字**：
nova 的帳本一次執行一個檔，跨執行什麼都不做。

### ④ 執行控制 — 缺「審批閘」

| | |
|---|---|
| 現況 | 逾時、停止條件（步數＋token）、模型路由、回頭邊 |
| 缺什麼 | 規格 §2.1 明列的**審批閘**。`src/nova/契約/工作流.py` 的 `種類` 只有 `模型／判準／審查`，**沒有人類節點可以住的位置** |
| 形狀 | `種類` 多一個值，狀態機走到它就停下等外部輸入；帳本記「等了多久、誰放行的」 |
| 缺在 | 迴圈（型別）＋載體（怎麼問人） |

### ⑤ 安全與治理 — 缺「人工簽核」

| | |
|---|---|
| 現況 | 三級權限、三家沙箱、`禁令.py`、機密不進版控。這格挖得最深 |
| 缺什麼 | 規格明列的**人工簽核**。`--全開` 一路走到各家的 `dangerously-*` 旗標，中間沒有確認點 |
| 形狀 | 權限升到全開時要一個外部確認；非互動情境要能用「事先簽好的授權」代替，否則 CI 會卡死 |
| 缺在 | 載體 |

sharktech 這格叫「環境約束」，內容一致。

### ⑥ 可觀測性 — 缺「遮罩」與「感測器歷史」

| | |
|---|---|
| 現況 | `載體/模型/記帳.py` 記模型呼叫、`載體/階段記帳.py` 記階段 |
| 缺什麼 | 一、**不記全文是靠「不記」不是靠遮罩**，所以帳本永遠答不出「它說了什麼」。二、`src/nova/載體/閘.py` 完全不寫帳本，9 條規則沒有觸發率資料 |
| 形狀 | 遮罩：白名單結構欄位＋雜湊，另案。感測器歷史：閘每跑一條就記一筆 |
| 缺在 | 載體 |

sharktech 把「人工審查介入點」也放在這格（規格放在⑤）。引用時要指名是誰的分類。

## 先做哪個：規則觸發率

Fowler 的〈sensors〉問了一句 04 一度以為沒人回答得了的話——她後來自己答了，逐字：

> "So I started **logging a history of sensor states every time they were checked**,
> to get some data."

而且列出這份歷史回答得了什麼（逐字轉述）：失敗頻率的趨勢是**指引或模型在進步**的訊號；
**從來不失敗的感測器**是「它不必要」的訊號；**常失敗的規則**是「該補指引」的訊號。

這條對 nova 特別便宜，因為零件都在了：帳本會寫、階段記帳已經在記判準紅綠、
讀取端有 `收斂`。**缺的只有一格——`src/nova/載體/閘.py` 不寫帳本。**

補上之後同時解掉兩個面：

```
⑥ 可觀測性  ← 規則觸發率有資料了
③ 持久化    ← 「長期觸發率為零的規則是刪除候選」＝第一個因為帳本而改變的決定
```

**那就是 Evidence 變成 State 的第一步**，而且它不需要新概念，只要接一條線。

## 什麼時候才寫 `class IHarness(Protocol)`

04 的結論不變（**現在不寫**），但這份文件讓那個條件變得可檢查：

> 出現**第二個載體實作**的那天才寫。在那之前，這六個面是**盤點用的分類**，
> 不是型別。

可檢查的判準：上面六格裡，有任何一格出現「兩種做法要在執行期互換」時，
那一格先抽成一個小 `Protocol`——**不是六個面一起抽成一個大介面**
（介面隔離：一個大 `Protocol` 會逼所有人實作用不到的方法）。
