# 接下來往哪走：先並行，再迭代，圖最後

跟 [`docs/設計/08-外面怎麼講載體工程.md`](08-外面怎麼講載體工程.md) 的分工：
**08 答「我們有什麼」，09 答「接下來做什麼、什麼順序、為什麼是這個順序」。**

需求原話是三件事：**完整的自我迭代、自我選擇 GRAPH、多 agentic 並行把事情做完。**
本文的第一個結論是：**這三件的依賴順序跟講出來的順序相反。**

```
講出來的順序   自我迭代 ──► 自我選擇 GRAPH ──► 多 agentic 並行
能做的順序     多 agentic 並行 ──► 自我迭代迴路 ──► 圖（推出來，不是畫出來）
                     │                  │                    │
                  產生 trace       把失敗變基礎設施      從 trace 推真依賴
```

沒有並行就沒有夠多 trace；沒有 trace 就推不出哪些邊是真的；推不出真依賴而先畫圖，
就是 [`docs/AGENT_ARCHITECTURE.md`](../AGENT_ARCHITECTURE.md) §8 的反模式一。

## 0. 這份的證據來自哪

一手實測五份、綜合三份、論文三篇，清單與交叉關係在 08 的第 0 節。這裡只留下推出結論的那幾個：

| 證據 | 數字 | 推出什麼 |
|---|---|---|
| OpenAI 的 agent-first repo | 5 個月、約 100 萬行、1,500 PR、3 位工程師起步 | 隔離與可讀性是前提，不是優化 |
| 同上 | 每週五 20% 時間清「AI 殘渣」，**不 scale** | 熵要機械回收，不能靠人發現 |
| Anthropic 的長時工作載體 | Planner 0.4%、審查 8.3%、建構 91% | 審查便宜；貴的話要查派工不是砍審查 |
| casys.ai 的 2,656 條指令 | 88.3% 含迴圈的指令在圖裡產不出原子動作 | 先畫圖的代價是可量的 |
| Google 的 SDLC 白皮書 | `Agent = Model + Harness`，約 10% 模型／90% 載體 | 投在載體的每一分都比換模型划算 |

## 1. 三個真缺口（其餘的已經有了）

盤點見 08 第 2 節。這裡只列**確認缺的**，每一條都核對過檔案：

### 缺口一：並行的隔離不是殼

兩個節點宣稱獨立、卻寫同一個檔——沒有資料依賴，但有寫入衝突。
這是「假獨立」，而它最難發現的地方在於**兩邊的提示互不提及**。

實際踩到過：一個排程工作流正在改 `src/nova/載體/命令列.py` 的某一段，
另一條線要改同一個檔的另一段。當時的處理是**手動開 git worktree**——
那是提示裡的懇求，nova 自己不知道有這回事。

`src/nova/載體/工作區.py` 不是這個：它是「結果未知時唯讀查工作區」，不是隔離。

**這一格分兩半，第一半已經做了**：`src/nova/迴圈/扇出.py` 現在會在派送前比對
各分支宣告的寫入範圍，撞在一起就拒絕整份計畫。**是拒絕不是護欄**——跟「分支數
超過上限」同一類：計畫本身就不成立，派出去只是白花兩個分支的錢，而護欄是
「跑到一半資源用完」那種。第二半（每個分支各自一個工作樹）還沒做，
所以**沒宣告寫入範圍的分支撞在一起時仍然攔不到**。

### 缺口二：trace 進不了 dataset

nova 有 trace（`src/nova/契約/帳本.py` 的十種事件），
有能力探針（`tests/整合/test_本地能力邊界.py`），**兩者之間沒有路**。

已經有一條這種路，但只覆蓋閘：`src/nova/載體/閘紅成票.py`
把符合條件的閘紅落成收件匣的一張票。**方向是把它延伸到模型失敗，不是重新發明。**

現在的狀況是：一次失敗跑完 → 帳本多一行 → 沒有任何東西因此在下次會紅。

### 缺口三：熵沒有人收

模型會照抄 repo 裡既有的模式，包括不好的那些，所以漂移是必然的。
現在的回收方式是**人手動發現**（路線圖五格過期、半套護欄的假綠，都是撞上才知道）。

`src/nova/載體/排程.py` 已經會定期醒來，缺的是掃描規則與開票的判準。

## 2. 「自我選擇 GRAPH」的正確形狀

最容易做錯的形狀是**讓模型畫圖**。正確的形狀是**載體從自己的帳本推出候選的邊，人批准**：

```
  帳本（trace）                真依賴的判準
  階段開始／結束               「下一步真的讀了上一步的輸出嗎？」
  工具呼叫                     沒有資料跨過邊界 ＝ 沒有邊
  節點的父邊與證據來源                │
        │                            │
        └────────────┬───────────────┘
                     ▼
            載體提出一張候選圖
                     │
                     ▼
                  人批准
```

判準來自論文那條線：evaluation topology 可以自動演化，
但**任務規格、安全約束、驗收公理必須留在人手上**。
那正是本專案「驗收權不在執行者手上」的同一條規則，換到圖這一層。

推導所需的原料已經在 `src/nova/契約/節點.py`（父邊、證據來源、邊包）
與 `src/nova/契約/帳本.py`。**缺的是那個推導函式，不是圖。**

## 3. 一個張力，不要讀反

OpenAI 那篇說他們用**最少的阻擋式合併閘門**，不穩定的測試靠重跑而不是無限期阻擋，
理由是「修正便宜、等待昂貴」。這跟本專案「閘要多、要擋」看起來相反。

看清楚兩件事就不衝突：

1. **他們的閘沒有變少，是往前搬了。** 架構不變量（固定分層、只允許往前依賴）
   由自訂 linter 與結構測試機械強制，而且錯誤訊息**刻意寫成能注入 agent 上下文的修復指示**。
   那就是本專案的提交閘。他們拿掉的是 PR 階段的阻擋，不是機械檢查。
2. **他們的前提條件這裡還不成立。** 「等待昂貴」是因為 agent 吞吐量遠大於人的注意力。
   本專案現在的瓶頸是驗證品質，不是吞吐量。

**所以這篇不是放寬合併閘的許可證。** 它給的是另一件事：
閘的錯誤訊息現在寫給人看，該改成也寫給執行者看——它是下一輪的輸入。

## 4. 路線：五階，有序

| 階 | 做什麼 | 為什麼在這個位置 | 先寫哪支會紅的測試 |
|---|---|---|---|
| 1a | **擋假獨立**（已做，#171） | 沒有它，並行的靜默覆蓋擋不住 | 兩個分支寫同一個地方 → **開跑前拒絕** |
| 1b | **worktree 真隔離**（已做，#176） | 1a 擋得住宣告出來的衝突，擋不住沒宣告的 | 兩個分支各自在自己的工作樹裡跑，互相看不到 |
| 1c | **跨程序閘鎖**（已做，#174） | 隔離解決了寫檔互撞，沒解決 CPU 互撞 | 三條同時跑閘 → 排隊，不是一起變慢然後假紅 |
| 2 | **trace → 固定探針** | 把閘紅那條路延伸到模型失敗 | 同一類失敗第二次出現 → 自動落票／落一支探針 |
| 3 | **熵回收：機械原則 ＋ 背景掃描** | 排程已經在跑，只缺掃描規則 | 偵測到漂移 → 開重構票，而不是等人撞到 |
| 4 | **從帳本推真依賴** | 這時候才有夠多 trace | 推出來的邊與現在的階段順序有差 → 差異要看得見 |
| 5 | 圖 | 只有第 4 階拿得出證據之後 | — |

第 1 階最急：它已經發生過，而且只會更頻繁。

## 5. 不要做的三件事

1. **現在不要開 `src/nova/圖/`。** 三份材料沒有一份說要先畫圖，
   其中一份給了數字說明代價。這條已經寫在 CLAUDE.md，這裡只是補上外部佐證。
2. **不要把載體邏輯寫成自然語言。** 那篇論文自己的結論是程式碼在確定性上勝出，
   只有高層協調政策適合自然語言——而本專案的核心主張就是「殼裡的才是保證」。
3. **不要因為別人說「少閘」就放寬合併閘。** 前提不成立，見第 3 節。

## 6. 一天長什麼樣（做完之後）

**現在**：一件事丟進收件匣 → 排程醒來 → 一條鏈跑完 → 撞護欄或做完 → 人來看。
一次一件，撞牆了人才知道。

**做完第 1～3 階之後**：

```
你丟三件互不相干的事進收件匣
        │
        ▼
  載體看依賴：三件動的檔沒有交集 ──► 三個 worktree，同時跑
        │                              有交集的那兩件 ──► 排隊，不是同時
        ▼
  跑完各自開 PR，閘各自跑
        │
        ├─ 全綠 ──────────────► 等你點頭
        │
        ├─ 閘紅 ──────────────► 已經會落票（今天就有）
        │
        └─ 模型失敗（同一類第二次）──► 落一支探針，下次會紅（第 2 階要補的）
                │
                ▼
        背景排程掃漂移 ──► 發現半套的假綠、過期的文件 ──► 開票（第 3 階要補的）
```

差別不在「跑得比較快」，在**你不必在場也不會靜默失敗**：
撞牆會留下票、失敗會變成下次的紅、漂移會自己浮出來。
