# 03 · 角色與工作流：把 TDD 規則變成會執行的東西

> 依 `AGENT_ARCHITECTURE.md` §3.2：一個迴圈要湊齊七欄位才算成立。缺 stop rule 的不是迴圈，是成本漏洞。

## 三個形狀

```
語言模型（腦）      詢問(提示) → 回應          可換：claude／codex／agy／本地
    ↑ 被持有
角色（身分）        固定的系統提示 ＋ 一顆腦     換腦不換身分
    ↑ 被組合
工作流（流程）      狀態機決定下一步            回頭邊由表表達
```

`角色` 與 `語言模型` 都是 `Protocol`（結構型），不是基底類別：只要形狀對就能替換，
被替換的那方不必知道我們存在。mypy strict 是唯一能機械檢查里氏替換與介面隔離的東西。

`固定提示角色` 是**組合**：它**持有**一顆腦，不繼承任何東西。
`建TDD執行器(角色表, 跑判準)` 是**工廠函式**，不是 `BaseWorkflow` 基底類別——
繼承會把父類的每一個決定綁在子類身上，組合只綁明確持有的那部分。

## 為什麼是狀態機，不是鏈式／Rx

兩件事被混在一起了，要拆開：

| 層 | 形狀 | 特徵 |
|---|---|---|
| 一次呼叫內的**訊息流** | 管線／鏈式是對的 | 同一件事的連續處理，**沒有回頭邊** |
| 角色之間的**控制流程** | 狀態機（表）是對的 | **有回頭邊**：驗證綠沒過退回實作、驗證紅沒紅退回測試 |

鏈式表達不了回頭邊。Rx 的 `retryWhen`／`repeatWhen` 是把迴圈藏進 closure，藏進去之後：

| | 轉移表（資料） | 鏈式（closure） |
|---|---|---|
| 印得出來嗎 | ✅ 直接 dump 進 journal | ❌ 控制流程在函式裡 |
| 測得動嗎 | ✅ 純函式，零 LLM | 🔶 要跑起來才知道 |
| 加階段 | ✅ 加一列（開放封閉） | ❌ 改鏈 |
| mypy strict | ✅ | 🔶 長泛型鏈很痛 |

而且加 RxPY 是多一個相依，做的是標準庫做得到的事——`寫程式.md` 的階梯會擋。

**訊息流那一層之後真的會寫成管線**：journal／遮罩落地時，`for 訊息 in 詢問(任務)` 後面
接一串純轉換。那是下一階的事。

## 這不是圖層

規格的圖層管的是「多條路徑之間該走哪一條」。這裡是**單一路徑加兩條回頭邊**，
屬於迴圈七欄位裡的 action policy 與 stop rule。CLAUDE.md 明文：在拿出 trace
說明哪條路徑分歧到線性寫不動之前，新增 `src/nova/圖/` 算違規。

## 五個階段的順序，以及為什麼驗證不是角色

```
測試(模型) ──→ 驗證·紅(機械) ──→ 實作(模型) ──→ 驗證·綠(機械) ──→ 審查(模型，換一顆腦)
                    │                                │
                    ↓ 竟然是綠的                      ↓ 沒綠
               退回 測試                          退回 實作
          （一支永遠綠的測試等於沒有測試）          （fallback）
```

順序不是挑的，是規則的明文：**先寫會紅的測試 → 跑它，親眼看到它紅 → 最少的碼讓它綠 → 全綠下重構**。

**驗證是機械判準，不是角色。** 硬規則 4 禁止同一個模型自寫自評；
2026-08-24 的定調是「驗收權不在執行者手上」。驗證若是 LLM，判準就變成模型說了算。

而且它**出現兩次**——實作前確認測試真的紅了（那就是負控），實作後確認全綠了。

`審查` 是模型，但呼叫端應該給它**另一顆腦**。自己審自己等於沒審。
這條目前**只有文件、沒有測試背書**，見已知缺口。

## 審查的驗收權在判定上，不在「子程序有沒有跑完」上

審查階段一度歸在 `種類.模型`。模型階段的規則是「跑完就算達到期望」，
所以——

> **審查員回「設計有重大問題，不通過」，只要 CLI 的結束碼是 0，
> 工作流照樣宣布「全綠且通過審查」。**

`CLAUDE.md` 硬規則第 4 條說不得以「模型說完成了」當停止條件。
原本的實作比那還鬆：**它連模型有沒有說完成都不看，只看子程序有沒有跑完。**

這是這個 repo 最在意的那種假成功，而且是 nova 自己造的——跟 agy 生圖回報
`status: SUCCESS` 卻沒有檔案是同一類。

### 修法：第三種階段種類

`種類` 從兩個變三個，正好對上 `docs/設計/04-載體要長什麼樣.md` 引的 Fowler 分類：

| 種類 | 對應 | 驗收 |
|---|---|---|
| `模型` | inferential guide——它去做事 | 跑完就算 |
| `判準` | computational sensor——機械跑一條指令 | 看退出碼 |
| `審查` | **inferential sensor**——另一顆腦來挑毛病 | **看它給的判定** |

判定走一個 ASCII 標記，角色提示原樣教給審查員：

```
REVIEW: PASS                 沒問題，可以收工
REVIEW: CHANGES-REQUESTED    有該改的地方，會退回實作員
```

`讀審查判定` 取回覆裡**最後一個** `REVIEW: X`——實測模型會先寫
「我會在最後給 REVIEW: PASS 或 REVIEW: CHANGES-REQUESTED」再給真正的判定。

### 三條出口，而 `階段定義` 只放得下兩條

| 判定 | 去哪 |
|---|---|
| 通過 | 完成 |
| 要求修改 | **退回實作**（第三條回頭邊） |
| 沒給結論 | **中止** |

第三列是整個修法的重點。**「看起來沒問題」不是判定**——沒有約定的標記就沒辦法
分辨「它審完覺得可以」與「它根本沒審、只是隨口回一句」。fail-closed：
讀不出來就停下來讓人看。

### 為什麼要標記而不是叫它「說清楚通不通過」

規格 §4.3：跨層傳遞一律 schema 化，自由段落會逼下游重建上游語意。
這裡的下游是狀態機，而它重建錯的後果就是宣布一個假的完成。

標記走 ASCII（`CLAUDE.md` 的跨程序 semantic id 例外）：要能被 grep、被別的程式讀，
而且模型對英文大寫標記的服從度比中文穩。

實跑驗證：`nova 工作流 --用 codex --審查用 agy`，agy 照約定在回覆最後給了
`REVIEW: PASS`，工作流走到完成。

### 這個 bug 是怎麼被抓到的

**不是機械閘抓到的，也不是我自己看出來的。** 是把設計文件
`docs/設計/04-載體要長什麼樣.md` 丟給 `codex --模型 gpt-5.6-sol`（唯讀，讀得到整個 repo）
審查時，它指著 `src/nova/迴圈/狀態機.py` 的行號說：

> 審查員回覆「設計有重大問題，不通過」，只要 CLI exit 0，Nova 仍會說「全綠且通過審查」。
> 帳本只會忠實保存這個假結論。**這比沒有歷史 trace 更急。**

這正是 inferential sensor 的用途，也是硬規則 4「不得讓同一個模型自寫自評」的實證：
同一顆腦寫的文件與程式碼，換一顆腦來看就看到了。

## 七欄位落點

| 欄位 | 這裡是什麼 |
|---|---|
| Trigger | 呼叫 `跑工作流` |
| Goal | 走到 `結束(完成)` |
| Memory | `軌跡`——**只帶上一步**給角色，不重播整段（context 會線性膨脹） |
| Action policy | 轉移表，只准走表上有的路 |
| Evidence | 每步的 `步驟結果`（終局＋判準紅綠＋證據） |
| Feedback | 紅掉時退回哪個階段，由表決定 |
| **Stop rule** | `最多步數`（預設 12）＋ **結果未知一律停** |

**結果未知一律停**蓋過所有階段的個別轉移：不知道做了沒的時候，往下走或退回重做
都可能把已經做過的事再做一次（at-most-once，寧漏不重）。

## 用 StrEnum 不用 Literal ＋ 常數表

識別字中文、值 ASCII。一個來源就沒有漂移問題——常數表與型別標註分兩處寫遲早對不上，
之前為此還特地寫了一支「兩邊要一致」的測試，改成 enum 之後那支測試可以刪掉。
而且能 `for 代碼 in 失敗代碼` 迭代，窮舉性測試才寫得出來。

## 接力：`[llm, llm, llm]`

`用` 給一串（`["codex","agy"]` 或 `"codex,agy"`）就是接力——前一顆失敗換下一顆。
`接力腦` 本身也實作 `語言模型`，所以它能被 `角色` 持有，也能被套進另一條鏈（組合）。

**能不能換下一顆，要看權限**——這是整個接力最關鍵的一條：

| 上一顆的終局 | 唯讀 | 可編輯 |
|---|---|---|
| 成功 | 不用換 | 不用換 |
| 確定失敗（請求沒出門） | 換 | 換 |
| **結果未知**（可能做了一半） | **換** | **不換** |

唯讀沒有副作用，重做是安全的；可編輯可能已經改了檔案，換一顆就是**做第二次**。
這就是 at-most-once 落到接力上的樣子，也是為什麼終局非得是三值不可——
布林會把「結果未知」壓成「確定失敗」，然後接力就會去重做副作用。

全掛時要留下**試過誰、各自為什麼**（`[接力 codex:auth → agy:model-not-found] …`）。
只給最後一顆的錯誤，上游語意就丟了（§4.3）。

`派工` 的兩條鏈**不准有交集**——同一家同時做事又審自己等於沒審。

### 逾時預設 30 分鐘，因為代價不對稱

逾時 → `結果未知` → 可編輯模式下接力**當場停、不准換腦**（可能已經改了檔案）。

所以**砍太早不只是慢，是把可回復的工作變成不可回復的歧義**；
等太久的代價只是等。而且高階模型與高推理強度本來就慢。
不對稱的兩邊，往安全那邊倒——要短就在呼叫端明講，不要靠改預設。

## 已知缺口

1. ~~`審查` 要換一顆腦沒有測試背書~~ **已解**：`nova 工作流` 的 `--審查用` 是必要參數，
   而且不能跟 `--用` 同一家，由 `Test工作流的換腦保證` 背書。
2. ~~還沒接真角色與真判準~~ **已解**：`nova 工作流 --用 codex --審查用 agy` 實跑過一輪完整 TDD。
3. **`階段表` 參數目前沒被用到**（只有一張表）。原本我判斷它違反 YAGNI，
   但使用者已經點名要 **ask／討論／多人互評**三種工作流——呼叫端存在，留著是對的。
4. ~~角色失敗時只有「中止」一條路~~ **部分解**：`接力腦` 讓一個角色可以換腦重試。
   但**工作流層還是只有中止**——階段失敗不會退回上一階段換人做。那是下一步。
5. **`模型` 在接力鏈上是共用的。** `--模型 does-not-exist` 會同時套到 codex 與 agy，
   但各家的模型命名空間不交集。要逐家指定模型，得把 `模型` 也做成對照表。
   實測時看到的：兩家都回 `model-not-found`，接力正確運作但兩顆都不可能成功。

## 拿它蓋自己：門面那一輪

`src/nova/__init__.py` 的門面**是 nova 自己派工做出來的**。分工：

```
人／Claude ── 寫任務書（簽章、行為要求、驗收標準、專案規矩）
     ↓
nova 工作流 ── codex 寫測試 → 機械判準驗紅 → codex 實作 → 機械判準驗綠 → agy 審查
     ↓
人／Claude ── 看軌跡、看 diff、跑閘、決定進不進 PR
```

**回頭邊真的觸發了**：

```
→ test        · success
→ verify-red  綠 ← 沒紅！這支測試沒在測東西
→ test        · success   ← 退回重寫（fallback）
→ verify-red  紅 ← 這次真的紅了
→ impl / verify-green / review
```

codex 第一次寫出來的測試是綠的。狀態機把它退回重寫——「一支永遠綠的測試等於沒有測試」
這條保證，第一次在真實工作上生效。

### 驗收時抓到的兩個問題（機械閘抓不到）

八條閘全綠，但人審抓到兩件事：

| 問題 | 為什麼閘抓不到 |
|---|---|
| `派工` 把同一個 `執行檔` 同時給 `用` 與 `審查用` 兩家 | 兩家是不同的二進位。假 CLI 不會抱怨，真跑才爆 |
| 一支測試同時驗四件事 | 測試會過。但紅了不知道是哪個保證壞掉 |

第一個補了 `審查執行檔` 參數並附負控；第二個把測試拆成六支。
**這說明「全綠」不等於「做對了」**——閘是必要條件不是充分條件。

## 實跑過一輪

```bash
uv run nova 工作流 --用 codex --審查用 agy --工作目錄 <某個 repo> "在 X 新增函式 Y"
```

codex 寫了含三組參數的測試（含負數與空清單）→ 判準確認它紅 → codex 寫了一行 `sum` 實作
→ 判準確認全綠 → agy 審查說設計已達最簡。五步走完，`done`。
