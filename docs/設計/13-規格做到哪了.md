# 規格做到哪了：逐節對照 nova 的現況

對照的對象是 [`docs/AGENT_ARCHITECTURE.md`](../AGENT_ARCHITECTURE.md)——**外部規格原文，一個字都不准改**。
這份表只回答一個問題：**它要求的東西，nova 有沒有。**

在這份表出現以前，「下一批做什麼」靠人記，而人會漏。

## 判準

「nova 現在」只有三種值，沒有第四種：

| 值 | 意思 |
|---|---|
| 有 | 指得出檔案**與**測試，而且那一條要求已經被包住 |
| 半套 | 指得出有什麼，**也講明缺什麼**（實作在、但沒有測試釘住，一樣算半套） |
| 沒有 | 指不出檔案也指不出測試 |

「我看過 code 覺得有」不算證據——**只以印象存在的東西等於不存在**，
那正是這個 repo 的判準。所以填「有」與「半套」的列，證據必須是真的存在的路徑或測試名，
由 `tests/驗收/test_文件即事實.py` 守。

**「快做完了」一律寫半套。** 灌水不會讓東西變出來，只會讓下一批做錯方向。

## 所以下一批該做什麼

從缺口裡挑三條：**§4.3 的隔離工作區、§7 的診斷表、§3.6 的存檔。**
其餘缺口不是不做，是還沒到它們最便宜的時候。

**一、§4.3 隔離工作區接到扇出上。** 兩半已經各自存在——工作樹開得出來、寫入範圍相交也擋得掉——
缺的只是中間那條線：扇出實際派工時不會替分支開工作樹，所以它是成本最低的一格。
它擋的風險也最實：兩個分支同時寫一個檔的失敗長得像模型變笨，會被誤診成別的層的問題。

**二、§7 的診斷表。** 挑它是因為它是**別條缺口的前提**：現在「這次失敗屬於哪一層」
只活在提示裡（§1.2、§5、§12 診斷 agent 三列的缺口是同一個），是虛線的懇求。上線前檢核清單、
指標彙總這兩條缺口都是「讀帳本」的衍生物，等症狀到層的歸屬變成查得到的表之後幾乎是免費的；
在那之前先做它們，會做出一份沒有人回答得了的清單。

**三、§3.6 的存檔。** 現在一次失敗跑完只是帳本多一行，下一輪不會因此有任何不同——
規格說得很直白：沒有存檔＝重試，有存檔＝定向進化。挑它不是因為四步循環全都要做，
而是因為存檔是那四格裡**唯一不需要新的模型呼叫**的一格。
但它排第三而不是第一，因為**現成的資料回餵不了**：帳本的全文是遮過而且會截斷的，
階段證據只留長度與雜湊（`src/nova/契約/工作流.py`、`src/nova/載體/階段記帳.py`）；
`src/nova/載體/進度.py` 的進度檔記得住全文，卻沒有分數欄。
存檔要新開一份「嘗試＋分數＋回饋」的存放層，不是把帳本接上去就好。

**不挑具名升級路徑**（§3.3 與 §8.3 兩列缺的同一塊），雖然它在表上出現兩次：
「誰接手」要先答得出「這次失敗屬於哪一層」，否則升級只是把同一句
「agent 表現不好」轉寄給人。它排在 §7 之後，不是不做。

不挑圖層本身（§4.1 的節點、路由、§6 的 GraphSpec 那一批）的理由跟原本一樣：要開那一層，先拿出 trace。
上面這三條都在產 trace，順序沒有變。
