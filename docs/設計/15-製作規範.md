# 15 製作規範：怎麼做才又快又穩

**快**＝一張票一次起跑就收在 0。**穩**＝每條保證都有會紅的測試。
兩者用同一把尺量：**起跑次數／票**。起跑次數降，速度就升，而且不是靠放寬任何護欄換來的。

這份規範是**共用的**：跟做的是哪個專案無關，之後做別的、或整個重做，用的都是這一份。
所以這裡**不寫票號、線號、進度**——那些會過期的東西住在專案的派工佇列裡。
這裡只寫兩件事：規範本身，和它的把關器該長什麼樣。

## 一、三層：提示說形狀、殼說界線、尺說有沒有效

```
角色提示   「好的輸出長什麼樣」   便宜、先做、但只是懇求，可以被忽略
    │
把關器     「做了什麼會被擋」     測試／閘／hook，執行者不用知道、也違反不了
    │
起跑次數   「這兩層有沒有用」     提示與把關器都改完，看這個數字有沒有降
```

三層缺一不可，但**只有第二層算保證**（CLAUDE.md：只以文件或提示形式存在的規範等於不存在）。
第一層的價值是省掉退回的輪數；第三層的價值是讓第一層的修改有東西可驗——
提示沒有測試能守，唯一的驗收就是起跑次數。

## 二、規範表：一條規範配一種把關器

| # | 規範 | 把關器該長什麼樣 | 在 nova 裡的落點 |
|---|---|---|---|
| 1 | 保證住在殼裡，不住在提示裡 | 一張規則表，提交前與 CI 各跑一次；單元層不准 fork | `src/nova/載體/規則表.py`；`tests/驗收/test_專案骨架.py::test_單元層不准fork子程序` |
| 2 | 每條保證做過一次負控；刀錨在標記不錨在原文 | 負控登記檔＋CI 跑登記變異；錨點失效在推出去之前就紅 | `tests/負控/`；錨在標記尚未落地 |
| 3 | 票要小：最多 3 支指名測試、錨符號名不錨行號、先列既有測試改寫清單、宣告寫入範圍 | 收件時機械查；派工前比寫入範圍交集 | `tests/單元/test_分派單.py::test_沒宣告寫入範圍的項目不檢查`；三支上限尚無把關 |
| 4 | 實作員動了測試檔，第一次退回測試員帶清單，第二次才收 4 | 狀態機的回頭邊，不是護欄直接殺 | 尚未落地 |
| 5 | 沒有紅可寫的工作（文件、登記、fixture）不走 TDD 七階 | 動工前快照＋驗證紅推導出 red_first，不由人填 | 尚未落地 |
| 6 | 審查有範圍；範圍外的發現落後續票，不算退回 | 票上宣告範圍只給審查員；FOLLOW-UP 條目不進連續退回計數 | 尚未落地 |
| 7 | 判準用結構不用字串；「查不到」是型別不是 False | 三值回傳型別；比對用唯一鍵，命中≠1 就退出 | `tests/單元/test_護欄原因契約.py::test_結束的護欄原因標的是列舉不是任意字串`；其餘尚未落地 |
| 8 | 每條線的收場原因進帳；接著排看原因不看次數 | 成果帳有 `guardrail_reason` 欄；同原因不重排 | `tests/單元/test_成果.py::test_舊帳沒記到護欄原因與這次沒撞護欄分得開`；接著排尚未落地 |
| 9 | 收在 0 之後到合併零手工：分支、PR、CI 釘 SHA、清樹 | `收` 一條命令走完，中間任何一步失敗就整條失敗 | 分支與清樹、PR 標題與本文已落地 |
| 10 | 角色提示只寫「好的輸出長什麼樣」，改了要用起跑次數量 | 提示的必要句子有測試守著不被刪掉 | `tests/單元/test_角色提示.py` |
| 11 | 根因先修：會讓「每張票都多一輪」的洞，先修完再派產品票 | 決策層，沒有把關器；量尺是第三節 | 人守 |

「尚未落地」的列，對應的票號與線號查專案的派工佇列，不查這裡。

## 三、誰做什麼

```
主 agent      派工 ── 驗收 ── 決策 ── 收尾          （四件事，不寫實作、不補測試、不調上限）
                │
                ▼
工作流線       test → verify-red → impl → verify-green → refactor → verify-refactor → review
              寫的腦與審的腦不同對話；動了測試檔／步數／連續兩次退審 → 收 4，按起點表接續

唯一例外       驗證機器自己的洞：
              派工開樹 → 立刻殺線 → 主 agent 在樹裡寫 → 從 verify-green 接續
              閘、刀、審查、收 一樣跑；每次用掉例外都要寫進回報
```

派工前三個檢查：閘排隊 ≤ 4、樹已 ff 到 origin/main、`git diff --diff-filter=U` 是 0。

## 四、量尺：每輪看四個數

| 數字 | 從哪裡算 |
|---|---|
| 起跑次數／票 | 成果帳裡同一票鍵的筆數 |
| 併入／天 | 合併的 PR 數 |
| 收件匣趨勢 | 等著／處理中，處理中要往下掉 |
| 主 agent 動手件數 | 每輪回報，每一件都要有理由 |

提交閘本體在這台機器實測 8.5 秒（九條規則相加）；完整測試套件約兩分鐘是驗證成本，
不是 `收` 執行的提交閘成本。慢的是排隊等鎖，不是閘，量法在 [`14-閘慢在哪.md`](14-閘慢在哪.md)。
