# 15 製作規範：怎麼做才又快又穩

**快**＝一張票一次起跑就收在 0。**穩**＝每條保證都有會紅的測試。
兩者用同一把尺量：**起跑次數／票**。起跑次數降，速度就升，而且不是靠放寬任何護欄換來的。

這份規範跟「做的是 nova」無關：把關器全在 nova 的閘、收件、狀態機裡，
換一個工作目錄一樣生效（唯一寫死 nova 的那一處由票 `規則表與判準寫死nova工具鏈` 拆掉）。
所以之後做別的專案、或整個重做，用的都是這一份。

## 二、誰做什麼

```
主 agent      派工 ── 驗收 ── 決策 ── 收尾          （四件事，不寫實作、不補測試、不調上限）
                │
                ▼
nova 線        test → verify-red → impl → verify-green → refactor → verify-refactor → review
              claude 寫、sol 審；動了測試檔／步數／連續退審 → 收 4，主 agent 按起點表接續

唯一例外       驗證機器自己的洞（03、26、04、字串判準、09）：
              nova 派工 開樹 → 立刻殺線 → 主 agent 在樹裡寫 → 接續 verify-green
              閘、刀、審查、收 一樣跑；每次用掉例外都要寫進回報
```

派工前三個檢查：閘排隊 ≤ 4（`ls ~/.local/state/nova/鎖/閘.排隊 | wc -l`）、
樹已 `merge --ff-only --autostash origin/main`、`git diff --name-only --diff-filter=U` 是 0。

## 三、量尺：每輪看四個數

| 數字 | 從哪裡算 | 現在 |
|---|---|---|
| 起跑次數／票 | `已處理/` 裡同一票鍵的筆數；儀表板尚無此欄 | 平均約 3（今天 8 次撞測試檔護欄） |
| 併入／天 | `gh pr list --state merged` | 13（目標軌 2、重構 11） |
| 收件匣趨勢 | `nova 收件` 的等著／處理中 | 34／9 |
| 主 agent 動手件數 | 每輪回報 | 9 |

提交閘本體實測 8.5 秒（九條規則相加），慢的是排隊等鎖，不是閘：
