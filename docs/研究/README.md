# docs/研究/

**外部資料的摘要與出處。** 跟旁邊兩個資料夾的分工：

| 資料夾 | 裡面是什麼 | 誰說的 |
|---|---|---|
| `docs/設計/` | nova 自己的設計決定 | 我們 |
| `docs/決策/` | 為什麼這樣決定、當時的取捨 | 我們 |
| `docs/研究/` | **業界怎麼做、論文說什麼、數字與出處** | 別人 |

## 三條規矩

1. **原樣保留，不要「整理」成我們的結論。** 摘要一旦跟原文混在一起，
   之後沒人分得出哪句是出處說的、哪句是我們推的。要下結論就寫進 `設計/`。
2. **每份開頭要寫誰產的、什麼時候、用什麼題目問的。** 研究會過期，
   而過期的判斷需要日期與題目。
3. **裡面的連結是「回報當時的樣子」，不保證還活著。**
   特別是委派給 LLM 產的報告，可能帶有它自己工作區的 `file://` 連結——
   那些對別人是死的，留著只當作「它宣稱有一份更長的」。

## 為什麼要有這一層

CLAUDE.md 說「規格用程式碼表達，不要用散文」——那是對**我們的規格**說的。
外部知識沒有程式碼可以表達，但它會被拿來當決定的依據，
所以**出處要留下來**：下次有人問「8% 這個門檻哪來的」，答得出來。

實例：`serial-ratio` 那條閘的門檻與理由，整條來自
[平行測試競爭.md](平行測試競爭.md) 第 4 節（阿姆達爾定律與 15~25% 的季增長）。
