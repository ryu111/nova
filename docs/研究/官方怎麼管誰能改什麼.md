## 路徑粒度

**`tools` metadata 中是 0/34。** 上表列完全部實際值；值只包含工具名稱，以及 `Agent(...)`／`Workflow(...)` 所允許的子 agent／workflow，沒有任何檔案或目錄路徑。換言之，34 份定義在 metadata 層只表達「有沒有某工具」（外加可呼叫哪個 agent/workflow），沒有表達「`tests/` 可寫而 `src/` 唯讀」。

有些 agent 的**提示文字**另寫了路徑界線，但那不是 `tools` 欄位：`scaffolder` 只能寫被指定的單一 service 目錄（`plugins/code-modernization/agents/scaffolder.md:21`、`plugins/code-modernization/agents/scaffolder.md:23`）；`uplift-migrator` 只能改自己的 unit，且不得改共用檔（`plugins/code-modernization/agents/uplift-migrator.md:56`、`plugins/code-modernization/agents/uplift-migrator.md:58`、`plugins/code-modernization/agents/uplift-migrator.md:61`）；`test-engineer` 把用途限成指定 `modernized/` 目錄下的測試檔（`plugins/code-modernization/agents/test-engineer.md:55`）；`patch-generator` 只能改指定 scratch `WORKSPACE`（`plugins/claude-security/agents/patch-generator.md:18`、`plugins/claude-security/agents/patch-generator.md:20`）。`uplift-migrator` 還說 Write/Edit 是 workspace permission rules 能觀察與限制的介面（`plugins/code-modernization/agents/uplift-migrator.md:68`），但本批材料沒有出現那些 path grants 的宣告位置；**查不到其實際路徑規則**。

提示內對 `Bash` 的細分限制明確不是硬牆：`scan-researcher` 說「只能用唯讀命令」，緊接著承認這是 agent 自守的規則、不是 permission 會擋下來的操作（`plugins/claude-security/agents/scan-researcher.md:16`）；`scan-verifier` 同樣說這是 rule、不是 wall（`plugins/claude-security/agents/scan-verifier.md:36`）。

# 二、有沒有「產出者與驗收者分離」的實例？

先分清兩種「不同」：以下把不同的 `agentType` 算成不同角色；同一 `agentType` 的另一次獨立呼叫只算不同執行個體。按前者，7 支腳本中 **2/7** 把產出和判定交給不同角色；按後者則是 **4/7** 有獨立判定呼叫。

註：`plugins/claude-security/workflows/scan.js` 是無換行的單行壓縮檔，因此該檔所有出處只能標成 `plugins/claude-security/workflows/scan.js:1`。

## 不同 `agentType`：2 支

1. **`claude-security/workflows/scan.js`**：候選 finding 由 `claude-security:scan-researcher` 產生，最後由 `claude-security:scan-verifier` 以 REACHABILITY、IMPACT、DEFENSES 三個 lens 各投一票；必須 3 票全回來且至少 2 票為 `TRUE_POSITIVE` 才保留。producer、verifier 的型別、三票門檻、輸出 vote record 都在單行腳本中（`plugins/claude-security/workflows/scan.js:1`）。兩個角色的定義也分開：researcher（`plugins/claude-security/agents/scan-researcher.md:2`）、verifier（`plugins/claude-security/agents/scan-verifier.md:2`）。
2. **`modernize-extract-rules`**：`business-rules-extractor` 產出 fresh rules（`plugins/code-modernization/workflows/extract-rules.js:204`、`plugins/code-modernization/workflows/extract-rules.js:215`）；每條 rule 另交 `legacy-analyst` 查 citation 並回 `confirmed / refuted / wrong-citation`（`plugins/code-modernization/workflows/extract-rules.js:246`、`plugins/code-modernization/workflows/extract-rules.js:258`、`plugins/code-modernization/workflows/extract-rules.js:261`）。

## 獨立呼叫、但沿用同一 `agentType`：另 2 支

3. **`modernize-harden-scan`**：finder 是 `code-modernization:security-auditor`（`plugins/code-modernization/workflows/harden-scan.js:106`、`plugins/code-modernization/workflows/harden-scan.js:113`）；refuter 與 Critical/High confirmer 也是同一 `security-auditor` 型別，只是另開 agent 呼叫、給相反 stance（`plugins/code-modernization/workflows/harden-scan.js:141`、`plugins/code-modernization/workflows/harden-scan.js:153`、`plugins/code-modernization/workflows/harden-scan.js:161`、`plugins/code-modernization/workflows/harden-scan.js:184`）。
4. **`modernize-uplift-deltas`**：finder 與逐條 referee 都是 `code-modernization:version-delta-analyst`，分別在 Find 與 Verify 呼叫（`plugins/code-modernization/workflows/uplift-deltas.js:115`、`plugins/code-modernization/workflows/uplift-deltas.js:127`、`plugins/code-modernization/workflows/uplift-deltas.js:156`、`plugins/code-modernization/workflows/uplift-deltas.js:168`）。

其餘 **3/7 沒有 agent 判定階段**：`portfolio-assess` 每個 system 只有一個 survey 呼叫，之後只是程式計算 COCOMO index（`plugins/code-modernization/workflows/portfolio-assess.js:63`、`plugins/code-modernization/workflows/portfolio-assess.js:90`）；`reimagine-scaffold` 每個 service 只有 scaffolder 本身的回報（`plugins/code-modernization/workflows/reimagine-scaffold.js:61`、`plugins/code-modernization/workflows/reimagine-scaffold.js:88`）；`uplift-migrate` 每個 unit 只有 migrator（`plugins/code-modernization/workflows/uplift-migrate.js:301`、`plugins/code-modernization/workflows/uplift-migrate.js:304`）。

## 判定方能否修改被判定物

- **原始碼／工作樹**：上述 4 支有獨立判定呼叫的腳本，都用不含 `Write`／`Edit` 的判定角色。`scan-verifier` 的工具列是 `Read, Glob, Grep, Bash, Agent(explore)`（`plugins/claude-security/agents/scan-verifier.md:7`），提示要求唯讀（`plugins/claude-security/agents/scan-verifier.md:36`）；`legacy-analyst`、`security-auditor`、`version-delta-analyst` 都只有 `Read, Glob, Grep, Bash`（`plugins/code-modernization/agents/legacy-analyst.md:4`、`plugins/code-modernization/agents/security-auditor.md:4`、`plugins/code-modernization/agents/version-delta-analyst.md:4`），也分別明寫不得建立或修改檔案（`plugins/code-modernization/agents/legacy-analyst.md:65`、`plugins/code-modernization/agents/security-auditor.md:96`、`plugins/code-modernization/agents/version-delta-analyst.md:122`）。所以按官方提示意圖是**不能改原始碼**；但四者都有一般 `Bash`，因此這不是工具層的硬性 filesystem read-only，這個限制與第一題相同，是 prompt rule。
- **候選物件的欄位**：有 3 支允許判定結果校正 metadata。`extract-rules` 的 referee 可給 `correctedSource`，workflow 會換 citation、把 confidence 降成 Medium 並加 SME question（`plugins/code-modernization/workflows/extract-rules.js:114`、`plugins/code-modernization/workflows/extract-rules.js:120`、`plugins/code-modernization/workflows/extract-rules.js:276`）；`harden-scan` 的 judge 可回 `adjustedSeverity`，workflow 會改 finding severity，第二位 judge 分歧時也會降成 Medium 並標 human triage（`plugins/code-modernization/workflows/harden-scan.js:89`、`plugins/code-modernization/workflows/harden-scan.js:176`、`plugins/code-modernization/workflows/harden-scan.js:198`）；`uplift-deltas` 的 referee 可改 `fixClass` 或用 `correctedSite` 取代位置（`plugins/code-modernization/workflows/uplift-deltas.js:84`、`plugins/code-modernization/workflows/uplift-deltas.js:85`、`plugins/code-modernization/workflows/uplift-deltas.js:182`、`plugins/code-modernization/workflows/uplift-deltas.js:185`）。這些是 workflow 根據 verdict 重建／修改回傳物件，不是 judge 寫檔。
- **`scan.js`** 的 verifier schema 只有二選一 verdict 與 reasoning；程式只據票數保留或丟棄 candidate，沒有讓 verifier 改 candidate 欄位（`plugins/claude-security/workflows/scan.js:1`）。

另有一個不在 7 支 workflow 腳本裡、但 agent 定義明載的 fix 流程：`patch-generator` 改 scratch workspace，並明說不自審、由 independent verifier 與人類把關（`plugins/claude-security/agents/patch-generator.md:12`）；`patch-verifier` 沒有 Write/Edit（`plugins/claude-security/agents/patch-verifier.md:7`），且明令 inspect/test、never modify（`plugins/claude-security/agents/patch-verifier.md:16`）。這是「能改的 producer／按意圖唯讀的 acceptor」最直接的一例。

# 三、有沒有任何「申訴／爭議」機制？

## 結論與出口

**7/7 都沒有**這種完整形狀：執行者提交結構化「上游輸入有錯」申訴，再由另一個 agent／模型裁成「退回上游」或「本步失敗」。逐一檢查 7 支腳本的全部 schema：scan（`plugins/claude-security/workflows/scan.js:1`）、extract-rules 四份（`plugins/code-modernization/workflows/extract-rules.js:65`、`plugins/code-modernization/workflows/extract-rules.js:110`、`plugins/code-modernization/workflows/extract-rules.js:128`、`plugins/code-modernization/workflows/extract-rules.js:138`）、harden 兩份（`plugins/code-modernization/workflows/harden-scan.js:46`、`plugins/code-modernization/workflows/harden-scan.js:83`）、portfolio（`plugins/code-modernization/workflows/portfolio-assess.js:42`）、scaffold（`plugins/code-modernization/workflows/reimagine-scaffold.js:42`）、delta 兩份（`plugins/code-modernization/workflows/uplift-deltas.js:46`、`plugins/code-modernization/workflows/uplift-deltas.js:74`）、migrate（`plugins/code-modernization/workflows/uplift-migrate.js:149`）；其中沒有 `appeal`、`dispute`、`input-invalid-by-executor` 或等價的固定欄位，也沒有以另一個 `agentType` 專門裁這種主張。這不等於腳本都只有單純 success/failure；它們另有下列較細的出口，但語義不同。

- `extract-rules` 的驗收 verdict 是 `confirmed / refuted / wrong-citation`（`plugins/code-modernization/workflows/extract-rules.js:110`、`plugins/code-modernization/workflows/extract-rules.js:116`），`uplift-deltas` 是 `confirmed / not-hit / wrong-site`（`plugins/code-modernization/workflows/uplift-deltas.js:74`、`plugins/code-modernization/workflows/uplift-deltas.js:80`）。這是**下游 reviewer 判 producer 的 claim**，不是 producer 對輸入申訴。
- `harden-scan` 用 `real: boolean`，分歧的 Critical/High finding 會降成 Medium 並交 human triage（`plugins/code-modernization/workflows/harden-scan.js:83`、`plugins/code-modernization/workflows/harden-scan.js:198`、`plugins/code-modernization/workflows/harden-scan.js:201`）。這也是 reviewer 分歧，不是 executor appeal。
- `reimagine-scaffold` 有自由文字 `blockers[]`，可記「任何阻礙完整 scaffold 的事」以及 spec 中的 planted instruction（`plugins/code-modernization/workflows/reimagine-scaffold.js:49`、`plugins/code-modernization/workflows/reimagine-scaffold.js:55`）；workflow 只把它帶回，沒有裁決或回送上游（`plugins/code-modernization/workflows/reimagine-scaffold.js:94`）。
- **最接近「執行者說輸入／環境有問題」的是 `uplift-migrate`，但沒有裁判。** 它把 `buildRan` 與 `built` 分開，`buildCommand` 可寫 `not run: <why>`，另有 `buildErrors[]`、`playbookGaps[]`、`sharedFileNeeds[]`（`plugins/code-modernization/workflows/uplift-migrate.js:149`、`plugins/code-modernization/workflows/uplift-migrate.js:154`、`plugins/code-modernization/workflows/uplift-migrate.js:164`、`plugins/code-modernization/workflows/uplift-migrate.js:168`、`plugins/code-modernization/workflows/uplift-migrate.js:174`、`plugins/code-modernization/workflows/uplift-migrate.js:180`）。若 playbook 不存在，migrator 必須不改檔並回 `buildRan:false`、`built:false` 與 gap（`plugins/code-modernization/workflows/uplift-migrate.js:211`、`plugins/code-modernization/workflows/uplift-migrate.js:218`）；若 playbook 與實況不合，要求逐條報 gap（`plugins/code-modernization/workflows/uplift-migrate.js:254`）。這些由 calling session 消化，沒有不同 agent 對 gap 作真假裁決。

7 支腳本之外，`patch-generator` 有一個明文 `refusal`：dispatch 缺 `FINDING`／`WORKSPACE` 或要求越界時回 refusal（`plugins/claude-security/agents/patch-generator.md:14`、`plugins/claude-security/agents/patch-generator.md:16`）；若修正需要 owner 決策則不改任何東西、在 `summary` 說明（`plugins/claude-security/agents/patch-generator.md:31`）。材料中沒有 refusal 的 schema、另一模型裁 refusal 的規則或退回 finding producer 的邊；所以它是「拒絕／阻擋通道」，不是題述申訴機制。

## 退回重做的邊

- **嚴格的「目前 phase 退回前一個 named phase」：0/7。** 三個 reviewer workflow 對錯誤 claim 是當場 drop／改欄位，不會送回 finder 重產：`extract-rules` 直接 confirm/correct/reject（`plugins/code-modernization/workflows/extract-rules.js:270`）、`harden-scan` 直接 survivor/refuted/demote（`plugins/code-modernization/workflows/harden-scan.js:171`、`plugins/code-modernization/workflows/harden-scan.js:195`）、`uplift-deltas` 直接 confirm/correct/drop（`plugins/code-modernization/workflows/uplift-deltas.js:177`）。
- **同一階段的 correction retry：1 支。** `scan.js` 對 inventory 做程式化完整性檢查；漏 top-level directory 時把缺項點名，退給 inventory agent **一次**完整重答，第二次仍不合則接受並記 partial，或 fallback 成整個 repository 單一 component（`plugins/claude-security/workflows/scan.js:1`）。agent 自己的定義也明寫漏目錄的答案會帶著缺項退回（`plugins/claude-security/agents/scan-inventory.md:22`、`plugins/claude-security/agents/scan-inventory.md:24`）。這是 controller 校正同一產出者，不是執行者申訴。
- **跨 invocation 的人工回邊：1 支。** `uplift-migrate` circuit breaker 遇到 0 個可跑 build，要求修正 build recipe 或改在 session 內做（`plugins/code-modernization/workflows/uplift-migrate.js:350`、`plugins/code-modernization/workflows/uplift-migrate.js:352`）；低於 2/3 build rate 時要求把 gaps/errors fold 回 `PLAYBOOK.md`、先用一個 failed unit 重驗，再以 `failedUnits + remainingUnits` 重呼叫（`plugins/code-modernization/workflows/uplift-migrate.js:354`、`plugins/code-modernization/workflows/uplift-migrate.js:356`）。結果把 `remainingUnits`、`failedUnits`、`blockedUnits` 都做成可直接再傳入的資料（`plugins/code-modernization/workflows/uplift-migrate.js:415`、`plugins/code-modernization/workflows/uplift-migrate.js:417`、`plugins/code-modernization/workflows/uplift-migrate.js:419`）。這條回邊由 calling session／人執行，不是 workflow 內自動跳轉，也沒有第三方裁判。
- **fix 流程（不在 7 支腳本）有 verifier→generator 重做。** generator 會收到上一輪 verifier 的 `OBJECTIONS`，workspace 已 reset，必須 fresh attempt 逐項處理（`plugins/claude-security/agents/patch-generator.md:29`）；verifier 的 REJECT 必須附可供 fresh attempt 修正的具體 objection（`plugins/claude-security/agents/patch-verifier.md:40`、`plugins/claude-security/agents/patch-verifier.md:44`）。方向是驗收者退回實作者，不是實作者反駁驗收輸入。

參考文件另列的是**命令／人工恢復模式**，不是這 7 支 JS 的執行邊：測試失敗後讓人選 fix-and-retry／skip／abort（`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:530`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:533`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:536`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:543`）；中斷後可 resume／restart／abort（`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:332`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:353`）；checkpoint 可從最後成功點恢復（`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:579`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:600`）；deploy 失敗可自動 rollback（`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:550`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:566`）。文件沒有「執行者聲稱前一階輸入錯、交獨立模型裁決」的例子。

# 四、schema 與結構化輸出，是怎麼防止「用散文含糊過去」的？

## 強制點與數量

7/7 支腳本都把每個 agent 呼叫綁到 JSON-Schema-shaped 的 `schema` option。靜態計數是 **15 個不同 schema object、18 個 logical dispatch site，18/18 都傳了 `schema`**；這裡的 site 是一個具名階段的呼叫設定，`scan.js` 共用的 `$e` retry wrapper 內部再次呼叫 `agent()` 不另算新 site（wrapper 與 7 個 schema-bearing 呼叫都在 `plugins/claude-security/workflows/scan.js:1`）：

| workflow | schema object 數 | dispatch site 數 | 宣告與綁定位置 |
|---|---:|---:|---|
| `claude-security scan` | 4 | 7 | inventory、threat model、finding、verdict 四種 schema；分別被 inventory、model、research、sweep、panel、repanel、red-team 呼叫使用，全部在單行檔（`plugins/claude-security/workflows/scan.js:1`）。 |
| `extract-rules` | 4 | 4 | `RULES_SCHEMA`、`VERDICT_SCHEMA`、`P0_SCHEMA`、`DTO_SCHEMA`（`plugins/code-modernization/workflows/extract-rules.js:65`、`plugins/code-modernization/workflows/extract-rules.js:110`、`plugins/code-modernization/workflows/extract-rules.js:128`、`plugins/code-modernization/workflows/extract-rules.js:138`），傳入點在 `plugins/code-modernization/workflows/extract-rules.js:218`、`plugins/code-modernization/workflows/extract-rules.js:264`、`plugins/code-modernization/workflows/extract-rules.js:313`、`plugins/code-modernization/workflows/extract-rules.js:351`。 |

機制的形狀就是 `agent(prompt, { ..., schema: SOME_SCHEMA })`；schema 用 `type` 約束 object/array/string/number/boolean/integer，用 `required` 要求不可省略的欄位，再用 `enum`／`pattern` 收窄值域。例如 finding 必須有 CWE、severity、source、title、exploit scenario、recommended fix（`plugins/code-modernization/workflows/harden-scan.js:46`、`plugins/code-modernization/workflows/harden-scan.js:54`）；scan finding 的 `cweId` 還要符合 `^CWE-[1-9][0-9]{0,4}$`（`plugins/claude-security/workflows/scan.js:1`）。security agents 的 prompt 也明令只回 dispatch 所要的 structured object、不要 preamble／narration（`plugins/claude-security/agents/scan-inventory.md:30`、`plugins/claude-security/agents/scan-inventory.md:32`、`plugins/claude-security/agents/scan-researcher.md:53`、`plugins/claude-security/agents/scan-researcher.md:55`、`plugins/claude-security/agents/scan-verifier.md:44`、`plugins/claude-security/agents/scan-verifier.md:46`）。

schema 之後仍有程式化 invariant，避免只靠 agent 自述：`uplift-migrate` 把 `built` clamp 成 `r.built && r.buildRan`，所以「沒跑 build 卻說 built」會被改成 false（`plugins/code-modernization/workflows/uplift-migrate.js:308`、`plugins/code-modernization/workflows/uplift-migrate.js:310`）；`scan.js` 另用程式核對 inventory 是否涵蓋每個 top-level directory、panel 是否 3 票全回且至少 2 票為真，並由程式計票（`plugins/claude-security/workflows/scan.js:1`）。

## schema 驗不過時

**平台層行為查不到。** 這批材料只有 `agent(..., {schema})` 的呼叫，沒有 `agent()`／workflow runtime 的實作，也沒有文件說 schema-invalid output 會由 runtime 自動重試、丟棄、回 null 或 throw。15 個 schema 也都沒有 `additionalProperties: false`；材料沒有說未宣告欄位是否會被拒絕。參考文件 `advanced-workflows.md` 講的是 Markdown command 編排、state、rollback 與人工 retry，沒有 `agent(...,{schema})` API 或 schema validation 規則（其範圍自述為 multi-step command sequences，`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:1`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:3`）。

腳本本身能確定的只有「falsey／null 結果之後怎麼辦」：

- `scan.js` 自己包了一層：initial call 沒結果後，按 8s、25s、90s、180s 四個基準延遲（再乘 deterministic jitter）最多重試 4 次，log 原因統稱 `died or was skipped`（`plugins/claude-security/workflows/scan.js:1`）。**推測：**若 runtime 把 schema-invalid 表示成 falsey，便會走這 4 次 retry；材料沒有證明這個前提。
- 其餘 6 支沒有腳本級 retry。`portfolio-assess` 將 falsey row 列為 `unmeasured`（`plugins/code-modernization/workflows/portfolio-assess.js:84`）；`reimagine-scaffold` 列為 `notScaffolded`（`plugins/code-modernization/workflows/reimagine-scaffold.js:88`）；`extract-rules`／`harden-scan`／`uplift-deltas` 多數以 `filter(Boolean)` 或 `if (!v) continue` 略過（`plugins/code-modernization/workflows/extract-rules.js:224`、`plugins/code-modernization/workflows/extract-rules.js:272`、`plugins/code-modernization/workflows/harden-scan.js:123`、`plugins/code-modernization/workflows/harden-scan.js:175`、`plugins/code-modernization/workflows/uplift-deltas.js:138`、`plugins/code-modernization/workflows/uplift-deltas.js:181`）；`uplift-migrate` 合成明確的未遷移失敗紀錄（`plugins/code-modernization/workflows/uplift-migrate.js:314`、`plugins/code-modernization/workflows/uplift-migrate.js:318`）。
- 若 runtime 對 schema failure 是 throw/reject 而不是回 falsey，這些主要呼叫周圍沒有專門針對 schema 的 `catch`；實際是否整階／整 workflow 失敗仍因缺 runtime 實作而**查不到**。`scan.js` 只有 max-effort adversarial 後處理有一般 catch，會保留第一輪 verdict 並記 incomplete，不能據此推成一般 schema 行為（`plugins/claude-security/workflows/scan.js:1`）。

## 固定選項

有。7 支腳本的 schema 共有 **14 個 `enum` 宣告**，分布是 `scan.js` 3、`extract-rules` 4、`harden-scan` 2、`uplift-deltas` 5，其餘 3 支為 0。

- scan：severity 只能 `CRITICAL/HIGH/MEDIUM/LOW`、confidence 只能 `HIGH/MEDIUM/LOW`、verdict 只能 `TRUE_POSITIVE/FALSE_POSITIVE`（`plugins/claude-security/workflows/scan.js:1`）。

## 在「多家 CLI、每次一個獨立子程序」下不能原樣搬的做法

以下是**不能原樣搬**，不是功能上永遠不能重建；共同原因是官方 JS 假設一個提供 shared globals 與 typed return 的 in-process workflow runtime，而 nova 呼叫之間沒有這個 runtime。

| 官方做法 | 不能原樣搬的原因 |
|---|---|
| `agent(prompt, {agentType, schema, phase, label})` 直接回已解析 object | `agentType` 是同一 plugin runtime 內的名稱解析，`schema` 是該 runtime 的呼叫參數；獨立 vendor CLI 只給 process exit/stdout/stderr，各家 agent 選擇與 structured-output 介面不同。官方的典型綁定見 `plugins/code-modernization/workflows/extract-rules.js:206`、`plugins/code-modernization/workflows/extract-rules.js:214`；材料又缺 `agent()` 實作，不能把這個 call ABI 帶去別家 CLI。 |
| `parallel([...thunk])`、`pipeline(items, stage1, stage2)` 與 runtime concurrency queue | 這些依賴同一 JS process 持有 promise、輸入陣列、回傳物件與 concurrency scheduler；獨立 subprocess 之間沒有共享 event loop。`reimagine-scaffold` 明說由 runtime 對 concurrency cap 排隊，並直接 `await parallel(...)`（`plugins/code-modernization/workflows/reimagine-scaffold.js:4`、`plugins/code-modernization/workflows/reimagine-scaffold.js:59`、`plugins/code-modernization/workflows/reimagine-scaffold.js:61`）；`scan.js` 的 `pipeline` 直接把第一 callback 產生的 `{component, model}` object 傳給第二 callback 啟動 research（`plugins/claude-security/workflows/scan.js:1`）。 |
| 跨呼叫的 in-memory `Map`／array／mutable object | `extract-rules` 用 process 內 `seen`, `confirmed`, `rejected` 跨 rounds 去重與累積（`plugins/code-modernization/workflows/extract-rules.js:184`、`plugins/code-modernization/workflows/extract-rules.js:190`）；`harden-scan` 用 `Map` dedupe（`plugins/code-modernization/workflows/harden-scan.js:129`）；`uplift-migrate` 在 while loop 內持有 `remaining/done/knownGaps`（`plugins/code-modernization/workflows/uplift-migrate.js:263`、`plugins/code-modernization/workflows/uplift-migrate.js:275`）。每次 nova 都是新 process 時，這些記憶不會自動跨呼叫存在。相對地，參考文件的 `.local.md` state 是 filesystem protocol，形狀不依賴 in-process memory（`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:281`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:315`）。 |
| runtime 的統一 falsey failure 與 retry wrapper | `scan.js` 假設 `agent()` 無結果時回 falsey，因此同一 helper 可以用相同 label/schema 重呼叫並統一記成 `died or was skipped`（`plugins/claude-security/workflows/scan.js:1`）。多家 CLI 的 timeout、非零 exit、空 stdout、非 JSON stdout、schema-invalid、拒絕各有不同 process 表現，沒有這個共同 falsey contract。 |
| shared token budget 與 integrated phase/log | `extract-rules` 可讀 `budget.total`／`budget.remaining()` 決定停止 rounds（`plugins/code-modernization/workflows/extract-rules.js:192`、`plugins/code-modernization/workflows/extract-rules.js:193`）；各 workflow 直接呼叫 runtime `phase()`／`log()`（例如 `plugins/code-modernization/workflows/uplift-migrate.js:271`、`plugins/code-modernization/workflows/uplift-migrate.js:289`）。不同供應商 subprocess 沒有共同 token ledger 或同一 UI event stream。 |
| agent frontmatter 的 `tools` allowlist／`model: inherit` | 這是 Claude agent loader 的設定：省略 tools 代表 full access，agent creator 又把 `inherit` 當預設 model 值（`plugins/plugin-dev/agents/agent-creator.md:102`、`plugins/plugin-dev/agents/agent-creator.md:103`、`plugins/plugin-dev/agents/agent-creator.md:110`）。材料沒有定義一套讓不同供應商 CLI 共同解讀這份 frontmatter 或 `inherit` 的協定；因此這個權限／模型表達不能直接充當跨 CLI 的 enforcement。 |

反過來，官方材料中以 filesystem 為邊界的做法不依賴 shared in-process runtime：scratch clone + staged diff（`plugins/claude-security/agents/patch-generator.md:12`、`plugins/claude-security/agents/patch-verifier.md:22`）、互斥 unit directories（`plugins/code-modernization/workflows/uplift-migrate.js:94`、`plugins/code-modernization/workflows/uplift-migrate.js:105`）、`.local.md` state/checkpoint（`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:281`、`plugins/plugin-dev/skills/command-development/references/advanced-workflows.md:579`）本身都是跨 process 可見的資料形狀。
