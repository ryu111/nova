# 登記的跑前體檢：錨點與覆蓋在跑變異之前就算得出來

## 現場

今天五次登記寫錯，回饋路徑都是「推 PR → 等 CI 幾分鐘 → 才看到 `WRONG_TEST`」。
兩道跑前檢查（錨點恰好一次、`該紅` 蓋得到被變異的那幾行）本身是對的，
問題是它們只在 `registered-mutation` 那條 CI 規則裡跑，一輪 158 秒
（`docs/設計/14-閘慢在哪.md`）。五次裡沒有一次需要真的套用變異才發現。

`tests/負控/跑前體檢.py` 把同樣那兩道判定提早：錨點只讀檔數字串，
覆蓋跑一次 `該紅` 收 coverage，**同一支測試被多把刀指名時只跑一次**。
判定沒有放寬，權威仍然是 `registered-mutation`。

## 固定負控

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| 把 `跑前體檢.體檢登記` 裡呼叫 `_驗覆蓋` 那一行換成 `pass` | `test_該紅蓋不到except分支的登記在跑變異之前就被指名` 要紅 | 紅：`AssertionError: 這一筆該被抓出來，實際：()` |

刀砍的是「砍 `except` 分支、而 `該紅` 只走 happy path」那個形狀
（今天實際踩到的第一類）：錨點對得上、測試也真的紅得起來，
唯一的破綻是那兩行一次都沒被執行——只有覆蓋這一關看得出來。
拿掉那一關之後體檢回報「全部過」，正是靜默放行的樣子。
