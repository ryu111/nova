# 號碼牌建了卻沒鎖住

## 固定負控

`_抽號碼牌` 建好牌之後那道 `flock` 就是「我還在排隊」。拿掉它，
`_牌的主人死了` 會把一個**活著的等待者**判成死人、把牌 unlink 掉——
那條當場被插隊，而隊伍看起來一切正常。

登記在 `tests/負控/登記們/閘鎖排隊順序.py`（識別：`號碼牌建了卻沒鎖住`，`最多秒=30`；
這一支真的 fork 子程序，預設的 `2.0` 會被牆鐘殺成 `RUN_ERROR`，那是假紅）。

| 破壞什麼 | 該紅的測試 | 親眼看到 |
|---|---|---|
| 刪掉 `閘鎖.py` 的 `fcntl.flock(牌.fileno(), fcntl.LOCK_EX \| fcntl.LOCK_NB)`（牌建了但沒鎖住） | `tests/整合/test_閘鎖先到先得.py::test_等到入隊才放下一條進場` | KILLED（2026-09-03T00:16Z） |

握手函式 `_等到號碼發到` 落地、那支先綠之後才驗，所以這個紅是變異造成的、不是假紅：

* 手動刪掉那一行跑
  `uv run pytest tests/整合/test_閘鎖先到先得.py::test_等到入隊才放下一條進場 -q`
  → **0.11 秒當場紅**（不必等逾時），訊息指名那張新牌：
  `牌 00000000000000000002 建了卻沒人鎖著——那條還沒真的入隊，或者建牌之後那道 flock
  根本沒下，它會被當成死人牌回收掉`；把行改回來之後轉綠。
* runner 那次（`tests/負控/test_登記的變異會被殺.py::test_登記的變異會被殺[號碼牌建了卻沒鎖住]`）
  也過了：基線綠、變異紅、覆蓋點得到那一行。

可重播的部分已經在版本裡了：登記那一列（識別 `號碼牌建了卻沒鎖住`）是機器跑的，
不靠這份紀錄的文字。
