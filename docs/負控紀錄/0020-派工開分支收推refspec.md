# 派工開的樹從第一秒就掛在分支上，`收` 推完整 refspec

## 現場

`派工` 開的樹過去是 `worktree add --detach`，`收` 推的是 `git push --set-upstream
origin HEAD`。git 回一句 `The destination you provided is not a full refname`——
而那時**閘已經全綠、commit 也成功了**：一整輪的工作卡在收尾的最後一步，
退出碼把它算成失敗，人得手動去救。42d695 就死在這一格。

治法是讓兩端長成同一個形狀：

- 開樹的當下就 `worktree add -b nova/<UTC時戳>-<票末六碼>`，分支名取自收件檔名的
  頭尾兩段，**全 ASCII**——repo 是 public，分支名會進 PR 的 URL，票標題那段中文
  不進來。相同分支名開第二棵樹要撞在 `worktree add -b` 上：那是「一條分支變兩棵
  樹」該被擋下的地方，不做 `-B`、不加後綴、不退回 detached。
- `收` 從 `git symbolic-ref --short HEAD` 讀分支，推 `HEAD:refs/heads/<分支>`；
  讀不到分支（detached）就當場停在退出碼 1，**一次 push 都不發**，訊息說清楚
  「這棵樹不是派工開的形狀」，不猜名字、不寫 `HEAD:refs/heads/HEAD` 那種
  「讓 git 不抱怨」的寫法。
- 誰開的誰收：`收掉工作樹` 把樹跟它掛的那條本地分支一起收。不刪的話扇出每跑一次
  就多積幾條 `nova/扇出-*`，而下一次同名派工會撞在一條沒人用的分支上。
  查分支那道 git 有三態——rc 0 是分支名、rc 1 是 detached（`-q` 讓它靜默）、
  其他非零是「這道 git 根本沒問成」。第三態要 raise，而且 raise 在
  `worktree remove` **之前**：問不出來就整件事不做，樹留著給人看。

## 固定負控

登記在 `tests/負控/登記們/派工開分支.py`（一線一檔，不往 `登記.py` 檔尾 append）。

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| `工作樹.py` 的 `worktree add` 把 `"-b", 分支` 換回 `"--detach"` | `test_開工作樹一定要把建分支參數交給git` 要紅 | KILLED |
| `收.py` 的 push 從 `f"HEAD:refs/heads/{分支}"` 換回裸 `"HEAD"` | `test_收把派工開的分支推成完整refspec` 要紅 | KILLED |
| `命令列.py` 的 `分支=_這條線的分支名(單.名稱)` 換成 `分支=f"nova/{單.名稱}"`（分支名帶中文） | `test_派工真的把樹開在ASCII分支上` 要紅 | KILLED |
| `工作樹.py` 刪分支那道 `_跑git或報錯` 換回 `跑git`（失敗靜默吞掉） | `test_收掉工作樹刪不掉分支要上拋` 要紅 | KILLED |

第三把刀砍的是**接線**不是 primitive：分支名這個值只有 `_子命令_派工` 那一行在組，
所以它配的測試必須從 `主程式(["派工", …])` 這端進去。直呼 `開一個工作樹` 的測試
全綠也擋不住它——三輪審查裡被記過的就是這一條（「沒走真實 `派工` 接線」）。

## 收場現在誠實停在 1

`收` 在派工開的樹上跑完會是：閘綠、push 成功、PR 開了也合併了，`gh pr merge
--delete-branch` 回 0（遠端分支收掉了），但本地那條 `nova/<時戳>-<六碼>` 還被
這棵樹佔著、沒刪掉 → `_查證本地分支已刪` 收 1，訊息指名是哪條分支卡住。
這是**誠實的 1**，不是假綠：樹與分支都還在，人手上有東西可以清。
「`收` 收掉自己那棵樹」是另一張票的事，不准在這裡用「被佔著就放行」把它壓成 0。
