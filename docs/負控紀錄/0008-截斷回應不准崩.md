# 端點中途斷線要收成結果未知，不准往外拋

## 現場

2026-09-01 22:35，三條線同時打同一顆本地 27B（權重 26 GB）：

```
22:35:46  oMLX  Memory pressure: soft -> hard (current=50.1GB, hard=49.2GB)
          → 把進行中的請求砍掉，回了截斷的 chunked response
          → nova 收到 http.client.IncompleteRead
          → 本地.py 的四個 except 一個都接不到
          → 整個工作流程序當場死掉
```

**`IncompleteRead` 不是 `OSError`，是 `HTTPException`。**
漏接的下場**不是失敗，是蒸發**：沒有退出碼語意、沒有帳本、沒有現場，
`nova 線` 只看得到「上一次怎麼收的：查不到」。

## 改法：判準從「例外叫什麼名字」換成「請求出門了沒」

四個 except 收成一支純函式 `_把例外收成回應`，終局由 `_出門了嗎` 決定：

| 情況 | 出門了沒 | 終局 | 為什麼 |
|---|---|---|---|
| `ConnectionRefusedError`、`URLError` | 沒有 | 確定失敗 | 連線建立不起來，urllib 在送出任何 byte 之前就包成它 |
| `IncompleteRead`、`RemoteDisconnected`、`ConnectionResetError` | **出門了** | **結果未知** | 連上之後才斷——工具迴圈可能已經改過檔案 |

**不去嗅 `URLError.reason` 的字串**：那個欄位有時是例外、有時是字串，靠不住。
只看是不是 `URLError` 這一族——中途斷的那幾種根本不長成 `URLError`
（`ConnectionResetError` 是裸的 `OSError`，另外兩個是 `HTTPException`）。

## 固定負控

| 破壞什麼 | 該紅的測試 | 親眼看到 |
|---|---|---|
| `_問得到的錯` 拿掉 `http.client.HTTPException` | `tests/單元/test_截斷回應不准崩.py::Test端點中途斷線::test_不准往外拋[截斷的chunked回應]` | KILLED |
| `_出門了嗎` 的判斷倒過來 | 同上，加 `tests/單元/test_本地失敗語意.py::test_URLError連不上歸類為未安裝` | KILLED |

登記在 `tests/負控/登記們/截斷不准崩.py`。

## 還沒解的那一半

記憶體壓力本身沒解——**三條線同時打一顆 26 GB 的模型**就是會撞。
這一格只讓它「撞了不會蒸發」，不讓它「不撞」。
本地呼叫要不要序列化是另一張票。
