# 階段代碼門面的公開全集必須直接源自 enum，不准手寫一份

## 現場

CLI-04 要給 CLI-05 一個窄介面：**哪些字串算合法的階段動作**。
最容易寫錯的形狀是手抄一份清單：

```python
公開階段動作全集 = frozenset({"test", "verify-red", "impl", ...})   # ← 會跟 enum 走散
```

走散的當下沒有人會發現：`階段代碼` 加一個成員，門面照樣「正常」運作，
只是**那個新階段對外永遠不存在**。錯誤訊息是 `未知的階段動作：<新階段>`，
看起來像使用者打錯字。

## 改法

`src/nova/載體/剖析器.py:19` 讓全集**由 enum 推導**，不留第二份真相：

```python
公開階段動作全集: frozenset[str] = frozenset(代碼.value for 代碼 in 階段代碼)
```

## 固定負控（2026-09-02 03:5x 實跑，主 agent 自己驗，未委派）

**破壞**：讓門面漏掉一個階段——

```python
公開階段動作全集: frozenset[str] = frozenset(
    代碼.value for 代碼 in 階段代碼 if 代碼.value != "review")
```

**該紅**：`tests/單元/test_階段代碼門面解析.py`

實測結果：

```
3 failed, 10 passed in 0.07s
  Test階段代碼門面解析行為::test_七個正典階段代碼皆可正確解析
      ValueError: 未知的階段動作：review
  Test階段代碼正典門面全集::test_門面動作清單直接源自階段代碼enum
```

**為什麼這一刀砍在這裡**：漏一個成員是「手抄清單」這個錯誤形狀的最小實例。
它同時打中三支測試——其中 `test_門面動作清單直接源自階段代碼enum` 是專門守
「不准有第二份真相」那一條，另外兩支是它的行為後果。
