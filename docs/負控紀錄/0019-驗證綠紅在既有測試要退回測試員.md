# 「全綠了嗎」紅在既有測試時要退回測試員

## 現場

`驗證綠` 的紅出口一律接回實作（`狀態機.py` 的 `出口標籤.紅: 階段代碼.實作`），
不看**紅的是誰的測試**。紅在既有測試時，實作員唯一能讓它綠的動作就是去改那幾支
測試檔——而那是它被禁止做的事，這條路走到底一定收在「不准動測試的階段」護欄
（實測：78f8ac、42d695）。改既有測試本來就是測試員的工作（對照 SWE-bench：
更新既有測試放在測試那一側的 patch，不放在模型 patch）。

判準粗細取選項 (i)：第一次紅仍退實作（可能只是實作員把行為改壞了），
**同一批既有測試連紅第二次**才退測試員。誰是「既有」只認判準證據的 `FAILED …::…`
行與這一輪的 `動過的測試檔`，不拿模型的自由文字判斷。

## 固定負控

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| 拿掉 `迴圈/狀態機.py` 的 `if _既有測試連紅該退回測試員(定義, 結果, 軌跡): return 階段代碼.測試`（＝子集判斷不算數，一律退實作） | `test_同一批既有測試連紅第二次就走回測試階並說明那幾支是既有測試` 要紅 | 紅：`AssertionError: 既有測試連紅第二次要退回測試員，不是再叫實作員撞一次護欄`（`At index 6 diff: <階段代碼.實作: 'impl'> != <階段代碼.測試: 'test'>`），同批的混合紅那支一起紅 |

刀砍的是**回頭邊接到誰**，不是分類器本身：`紅在哪些既有測試` 原封不動留著，
所以「分類器還在、只是沒人照它的結果轉向」這個最容易假綠的形狀正是這把刀的目標。
