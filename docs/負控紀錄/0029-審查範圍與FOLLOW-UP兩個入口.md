# 審查範圍宣告得出來、`FOLLOW-UP:` 是第二個入口、後續發現落得成票

## 固定負控

守的是「票的知識」跟「審查員的知識」從此是兩個集合：`ISSUE:` 是退回的入口，
`FOLLOW-UP:` 是後續票的入口。三把刀各砍一個接線點，砍下去就退回今天的樣子。

| 破壞什麼 | 預期被哪裡抓到 |
|---|---|
| `src/nova/迴圈/工作流.py` 接範圍給審查員那一格的條件改成 `if False:` | `tests/整合/test_審查範圍.py::test_票上宣告的範圍走得到審查員手上而且只到審查員[prompt]` |
| `src/nova/契約/審查問題.py` 的 `_問題樣式` 放寬到也吃 `FOLLOW-UP:` | `tests/單元/test_審查問題.py::test_FOLLOW_UP條目不算ISSUE也不進連續審查護欄[issue]` |
| `src/nova/載體/命令列.py` 落票前的去重判斷永遠說「還沒落過」 | `tests/整合/test_後續發現落成票.py::test_收0時FOLLOW_UP各落成一張帶來源與驗收的票重複的只落一張` |

登記在 `tests/負控/登記們/審查範圍.py`（一線一檔）。

## 實測

2026-09-03 跑 `tests/負控/執行器.執行變異`，三把刀全部 **KILLED**：

- **拆掉接給審查員那一段**：`任務.範圍` 照樣有值、佇列與門面那兩格照樣綠，
  只有「送到眼前」那一格紅——守的是「範圍真的送到審查員手上」，
  不是「有一個叫範圍的欄位」。
- **兩個入口併回一個**（就是今天的病）：`讀審查問題列` 把 `FOLLOW-UP:` 也吃進去，
  範圍外的發現又變成一次退回，兩輪之後撞 `連續審查要求修改門檻 = 2`。
- **落票不去重**：同一條後續在多輪重講就會多落一張票，而多輪重講在真實軌跡上是常態
  （票 21a 五輪、票 22 四輪都重講過同一批）。

三把刀砍在三個不同的檔上，互相不掩護。
