# 0010｜`派工 --起點` 護欄的負控

日期：2026-09-02
測試檔：`tests/整合/test_派工起點.py`
被護的行為：`nova 派工 --起點 <非 test>` 必須**在開新工作樹之前**以退出碼 2 擋下，
並在訊息裡給出**照抄就能跑**的接續指令（`nova 工作流 --提示檔 <票> --工作目錄 <那棵樹> --起點 <原起點>`）。

## 怎麼拿掉

把 `src/nova/載體/命令列.py` 的護欄整段拿掉（回到本票之前的狀態）：

```
git stash push -- src/nova/載體/命令列.py
uv run pytest tests/整合/test_派工起點.py -q -p no:randomly
git stash pop
```

即 `_子命令_派工` 開頭只剩原本那一句 `if "派工" not in sys.argv[1:]`，
沒有「起點不是 test 就擋下」這一段。

## 拿掉之後（負控：該紅的紅了）

`13 failed, 7 passed`——紅的正是護住這個行為的那些：

- `test_派工在有未提交紅測試的樹上收到非測試起點時當場擋下[verify-red／impl／verify-green／refactor／verify-refactor／review]`
- `test_擋下時給的是照抄就能跑的接續指令[同上六個起點]`
- `test_被擋下時不准開新樹也不准動到樹上的紅測試`
  （這一支的失敗輸出直接把 bug 印出來：`派出去了。線名：…／工作樹：…nova-wt-…`
  ——它真的在一棵**沒有那支紅測試**的新樹上把 impl 派了出去。）

沒紅的 7 支是「不准被一起改壞」的那一組：
`test_派工起點為測試時不被護欄擋下`、`test_工作流依然吃得下非測試起點[六個起點]`。
它們在有護欄／沒護欄兩種狀態都綠——這正是它們的任務：
證明護欄沒有波及 `--起點 test` 與 `nova 工作流` 那條正確的接續路徑。

## 裝回去之後

`6 failed, 14 passed`。剩下的 6 支紅在
「訊息裡那行指令沒有 `--提示檔 <票>`、工作目錄還是 `<那棵樹>` 這種佔位字」，
也就是 review 指出的「照抄後只會卡在 stdin」——那是這一輪 impl 要補的。

impl 補上「訊息帶真的 `--提示檔 <票檔>` 與真的 `--工作目錄 <那棵樹>`」之後：
`20 passed`。

## 安全帶

負控會讓 `派工` 真的去開樹、真的在背景叫模型起來（第一次跑就發生了，
留下 `nova-wt-…` 與活著的 `agy` 子程序）。所以那兩支 in-process 測試掛了
`開樹與發射都當場炸` fixture：`開一個工作樹` 與 `_發射背景程序` 被換成當場 `pytest.fail`。
**拿掉護欄做負控時，測試會炸在那道安全帶上，而不是真的派一條線出去。**
