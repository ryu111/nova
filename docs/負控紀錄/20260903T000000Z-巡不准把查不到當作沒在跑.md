# 巡的判定不准把「查不到在不在跑」當成「沒在跑」

## 固定負控

`是否在跑` 是三態：True／False／`None`（清查不到）。巡在放行前只認 `is False`
——`None` 當成沒在跑的話，巡會在一棵**可能正在跑**的樹上叫醒同一張票，
兩個工作流搶同一棵樹。拿 flock 當替代也擋不住：拿不到鎖那條路照樣會走
`_記下這次醒來`，把那棵樹的 `狀態.json` 覆寫成 `busy`，
剛寫進去的 `resume_not_before` 就被洗掉。

放行條件寫成一行 `return 在跑 is False`，而它長得就像可以簡化成 `not 在跑`
——那正是它要被一把刀釘住的理由。

| 破壞什麼 | 該紅的測試 | 親眼看到 |
|---|---|---|
| 在 `能不能叫` 開頭插一行 `return 在跑 is not True`，把三態壓成「不是 True 就是沒在跑」 | `tests/整合/test_巡的判定.py::test_查不到在不在跑就不算到期` | KILLED |

變異登記在 `tests/負控/登記們/巡判定.py`，錨點吊在 `def 能不能叫(` 那一行上
（不吊 docstring 或裸的 `is False`：措辭會被改寫、那三個字別處也長得出來，
錨點對不上要當場炸，不能靜靜打空）。
