# 0013｜「把門檻調低來換綠」三招各自的負控

日期：2026-09-02
測試檔：`tests/驗收/test_專案骨架.py`、`tests/單元/test_豁免登記.py`
被護的行為：2026-09-01 一晚出現四次的同一種病——測試紅了不修測試，改去把檢查關掉。
表格那三條（加 `E501` 豁免、整檔 `# ruff: noqa`、偷開 pytest 設定鍵）
各自重演一次，**親眼看到它紅**，再還原。

三條各做一次，各自獨立：合成一支的話紅了不知道是哪一種。

## 第 1 條：`pyproject.toml` 給 `tests/**` 加 `E501` 豁免

怎麼重演（真的改檔）：`[tool.ruff.lint.per-file-ignores]` 的 `"tests/**"` 陣列尾巴加 `"E501"`。

```
uv run nova 閘 ci
```

紅了（當時 13 條閘裡的 `ruff-exemptions`）：

```
[紅] ruff-exemptions  ruff 豁免登記
       ruff 豁免與登記表不一致。
       多了：per-file-ignores:tests/**:E501
       少了：無
       加豁免不是修 lint。要加，先改登記表並說明理由
```

還原後全綠。

## 第 1 條的延伸：只改登記表、不動地板值

原本的漏洞是「同時改 `pyproject.toml` 與登記表就無聲通過」。
現在登記表的大小寫死成 `ruff豁免數量上限`，加一條就必須**同時**動那個常數，
而動常數這件事在 diff 裡看得見。

怎麼重演：`src/nova/載體/豁免登記.py` 的 `期望ruff豁免` 加一條
`"per-file-ignores:tests/**:E501"`，**不動** `ruff豁免數量上限`。

```
uv run pytest "tests/單元/test_豁免登記.py::test_豁免清單只准變短不准變長" -q
```

紅了：

```
>       assert len(期望ruff豁免) <= ruff豁免數量上限
E       AssertionError: assert 33 <= 32
```

還原後綠。

## 第 2 條：整個檔案開頭加 `# ruff: noqa`

怎麼重演：`src/nova/載體/命令列.py` 第一行插入 `# ruff: noqa: SLF001`。

```
uv run pytest "tests/驗收/test_專案骨架.py::test_不准整檔關閉ruff檢查" -q
```

紅了，而且指名是哪個檔哪一條規則：

```
E       AssertionError: 發現整檔關閉 ruff 檢查（要豁免請寫在該行的行尾，不准整檔關閉）：
E         src/nova/載體/命令列.py:第 1 行（# ruff: noqa: SLF001）
```

還原後綠。順帶：本票也把既有的兩處整檔關閉拆掉了
（`tests/負控/執行器.py` 的 `EM101, EM102, TRY003`、
`tests/負控/test_登記的變異會被殺.py` 的 `I001`），改成真的把碼修好。

## 第 3 條：`[tool.pytest.ini_options]` 偷開新鍵

怎麼重演：在 `[tool.pytest.ini_options]` 加
`disable_test_id_escaping_and_forfeit_all_rights_to_community_support = true`。

```
uv run pytest "tests/驗收/test_專案骨架.py::test_pytest設定只准已登記的鍵" -q
```

紅了：

```
E       AssertionError: pytest 設定鍵與登記表不一致。
E         多了：disable_test_id_escaping_and_forfeit_all_rights_to_community_support
E         少了：無
E         加 pytest 設定鍵不是修測試。要加，先改登記表並說明理由
```

還原後綠。

## 還原查證

三條（含延伸共四次）都做完並還原，`uv run nova 閘 ci --全部跑完` 13 條全綠。
