# `收` 在派工樹上要把樹與本地分支一起收乾淨

## 現場

派工樹上的 `收`：閘綠 → push 成功 → PR 合併，然後 `gh pr merge --delete-branch`
在「目前分支＝head」時會先 `git checkout <base>`，而 base（main）正被主工作區佔著。
linked worktree 裡那道 `git checkout main` 回 128（`'main' is already used by
worktree at …`）——**merge 已經做完了才回非零**：`收` 收 1，樹與分支照樣留著，
下一次同名派工會撞在一條沒人用的分支上（`docs/負控紀錄/0010` 的現場）。
遠端那條分支本來就由 repo 的 delete-branch-on-merge 刪，`--delete-branch`
在派工樹裡沒有任何好結局。

治法把「收 0」的意思釘死：在派工樹上，收 0 代表**那棵樹不在了、它掛的本地分支
也不在了**。

- 拓撲在**第一個 git 寫入之前**問：`_開工前問清楚現場` 先讀分支（detached 就停），
  再問 `主工作區(根)`。問不出來就當場收 1，那時 commit、push 一道都還沒發。
  **不准 fallback**——「問不到主工作區就當它不是派工樹」跟「分支被佔著就放行」
  是同一種猜，兩次都被審查打回；查不到就大聲失敗。
- `是派工樹 = 主區.resolve() != 根.resolve()`：兩邊都 resolve，macOS 的
  `/var` 是 `/private/var` 的 symlink。
- 合併：派工樹只給 `--squash`；主工作區那條路照舊帶 `--delete-branch`。
- 合併之後才收樹（`收掉工作樹` 連本地分支一起收），收不掉就收 1，訊息指名分支並
  明講「不要重跑 merge」——merge 已經發生過了，沒做完的是清現場那一段。
- merge 之後 `根` 隨時會不見（樹把自己收掉），所以之後每一道指令的 cwd 只准是
  主工作區，`nova.載體.工作樹` 也放在模組頂端 import：樹沒了之後遲到 import
  樹內模組會炸。

## 固定負控

登記在 `tests/負控/登記們/派工開分支.py`（一線一檔，不往 `登記.py` 檔尾 append）。
`登記.py` 既有的兩把（`收尾合併不得使用管理員`、`收尾合併必須刪除分支`）因為
`_合併這個PR` 改成組 argv，錨點重釘到 `指令 = ["gh", "pr", "merge", "--squash"]`
與 `if 刪遠端分支:` 那兩行。

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| `收.py` 拿掉 `收掉工作樹(根目錄)`（合併完不收樹） | `test_收在派工開的樹上整趟走完要收0` 要紅 | KILLED |
| `收.py` 把 `刪遠端分支=not 是派工樹` 寫死成 `True`（派工樹誤帶 `--delete-branch`） | `test_收在派工開的樹上整趟走完要收0` 要紅 | KILLED |
| `收.py` 合併指令加上 `--admin`（重釘錨點） | `test_合併指令不准帶管理員旗標` 要紅 | KILLED |
| `收.py` 刪掉 `if 刪遠端分支: 指令.append("--delete-branch")`（重釘錨點） | `test_合併指令一定帶刪除分支旗標` 要紅 | KILLED |

第一把砍的是「收 0 的定義」：測試若只看退出碼，留著一棵沒人會再進去的樹照樣全綠，
所以那支測試看的是「跑完之後這個 repo 上還剩什麼」——樹不在、`branch --list` 是空的、
`worktree list` 只剩主工作區。第二把砍的是 argv 本身：`--delete-branch` 帶了之後
gh 仍會 merge 成功，紅只出現在退出碼與現場，光看「有沒有合併」是攔不住的。
