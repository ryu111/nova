# `--預算token` 是視窗累計，當不了單次上限

## 現場（2026-09-01 實測）

```
$ nova 問 --用 codex --預算token 3000000 ...
預算鎖：這段時間已經用掉 129759299 token，超過上限 3000000
```

**一次呼叫都還沒發出去就被擋。** `--預算token` 的語意是「這段時間內全專案最多花幾個
token」（預設視窗 24 小時），而那個視窗裡已經累積了 1.3 億。派工的人想講的
「這一次最多花 300 萬」在旗標表上根本沒有對應項。

## 三個 scope，三個名字

| 旗標 | scope | 誰在用 |
|---|---|---|
| `--預算token`／`--預算美金`／`--預算幾小時` | 全專案 N 小時視窗累計 | `問`、`工作流` |
| `--最多token` | 這一輪工作流的累計 | `工作流` |
| `--單次上限token`（新）／`--單次最多token` | 每一次模型呼叫 | `問`／`工作流` |

**不准把 `--預算token` 改成單次語意**：那會讓既有的視窗保護消失，而且消失得沒有痕跡。

## 固定負控

| 破壞什麼 | 該紅的測試 | 親眼看到 |
|---|---|---|
| 視窗那道關卡改拿 `_這次的單次上限(參數)` 去比（＝兩個上限的判斷對調） | `tests/整合/test_預算scope分名.py::Test視窗預算與單次上限互相對照::test_視窗已花1億3但單次上限內照常發送` | KILLED |
| `_視窗範圍`／`_單次範圍` 兩個標籤對調 | `tests/整合/test_預算scope分名.py::Test護欄擋下時JSON證據講得出是哪個Scope::test_單次超限的json證據標明範圍是單次呼叫並記下實際與上限`、`::test_視窗超限的json證據標明範圍是視窗累計` | KILLED |

登記在 `tests/負控/登記們/預算scope分名.py`，2026-09-02 跑過 runner，兩把刀都被殺。

第一把刀之所以要釘住：對調之後外表照樣有兩個旗標、照樣回護欄碼 4，只是擋錯人——
`--單次上限token 3000000` 會被 1.3 億的視窗歷史擋在模型呼叫之前，正是這張票要修掉的病。
第二把刀釘的是證據：退出碼 4 本身說不出是誰擋的，外圈靠 `上限判定.範圍` 決定
「換題目重派」還是「這個視窗今天收工」，標籤指反了就是反著決策。

## help 也要分得出來

`--最多token` 的說明只寫「累計」是不夠的：視窗那個也叫累計，兩行並排在同一份 help
裡讀不出差別。每個旗標的**說明文字本身**要認領自己的 scope，不能靠旗標名或 metavar
帶過去——那種驗法會自我滿足。守在
`tests/整合/test_預算scope分名.py::Test三個預算Scope的Help說明分明`。
