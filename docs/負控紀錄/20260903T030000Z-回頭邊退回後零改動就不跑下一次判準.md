# 回頭邊退回的模型階段零改動時，下一次判準不准跑

## 現場

「同一批紅且工作區雜湊未變連三輪才停」這條護欄只在**雜湊未變**時數得到 3，
而雜湊未變＝退回去的那個模型階段一個 byte 都沒動，下一次判準跑的是一模一樣的樹，
結果注定一樣。**第 2 次判準就已經是確定性重播**，第 3 次更是；護欄在「發現沒進展」
與「停下來」之間多放了兩輪。實測 530ff9：impl#2 150s＋vg#2 117s＋impl#3 114s＋vg#3 98s
＝ 479 秒、$1.03、15,365 output token 換到零資訊。

現在在判準開跑**之前**多量一次雜湊：這個判準上一次跑是紅的、中間隔著模型階段
（`狀態機.上一次同一個判準紅在第幾步`），而且雜湊等於那一次跑完時的雜湊
（`工作流._回頭邊後的重播`），就當場收 4，這次判準**沒有跑**。
繞幾步不影響：回頭邊直接退回來是重播，繞 `測試 → 驗證紅 → 實作` 一整圈回到同一個
判準、樹卻一個 byte 都沒動，一樣是重播——**一次真改動只換得到一次判準**。
觸發條件全機械，只認軌跡形狀與工作區雜湊，不認模型說的「我沒有改任何檔案」。

## 固定負控

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| 拿掉 `迴圈/工作流.py` 主迴圈「沒進展」串接裡的 `or _回頭邊後的重播(定義, 軌跡快照, tuple(工作區雜湊們), 任務.工作目錄, 階段表)` 那一行（＝算得出是重播也照跑；刪掉之後那串仍是合法語法，紅的是行為不是 SyntaxError） | `test_退回實作後工作區雜湊未變就不跑下一次判準`、`test_退回測試員後工作區雜湊未變也不跑下一次判準`、`test_退回實作後工作區雜湊有變就照跑那次判準` 要紅 | 紅：`assert '無進展' in '超過最多步數 35，停止…'`（判準一路重播到燒完步數）、`assert '無進展' in '「verify-red」連續 2 次是綠的…'`、`assert 9 == 2`（同一棵樹又跑了 7 次判準）；`test_首輪雜湊相等不算重播` 照舊綠 |

刀砍的是**主迴圈要不要提早收**，不是判定本身：`_回頭邊後的重播` 與
`上一次同一個判準紅在第幾步` 原封留著，所以「判定還在、只是沒人照它的結果停」
這個最容易假綠的形狀正是這把刀的目標。
