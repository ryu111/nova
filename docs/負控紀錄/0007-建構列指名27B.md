# 建構列指名型號：不靠 `/v1/models` 的清單順序

## 為什麼

`本地.py::_第一個型號()` 的註解寫著「**不寫死型號**——寫死的話換一顆模型
就要改 nova 的原始碼」。出發點對，但它拿的是清單的**第一個**：

```
Ornith-1.5-9B-MLX-4bit     ← 排第一，所以建構列實際拿到的是它
Ornith-1.5-9B-MLX-8bit
Qwen3.8-27B-4bit
Qwen3.8-27B-8bit           ← 想要的是這顆
Qwen3.8-27B-MTP-8bit
```

**「清單第一個」不是一個決定，是一個意外。** 端點多下載一顆模型、
或它換一個排序，建構列就靜靜換了一顆腦——而**帳本只記家族名不記型號，
所以看不出來**。9B-4bit 正是實測唯一會撞回合上限的那一顆。

型號指名在**派工表**裡，跟推理列指名 `codex高階模型` 是同一招：
它是**資料**不是程式碼，換模型改一行資料，不必動 `本地.py`。
型號常數住在它自己家族旁邊（`本地.建構型號`），派工表只引用。

## 這一格弄失效的兩把舊刀（已修）

| 刀 | 為什麼失效 |
|---|---|
| `建構列不由local打頭` | 錨點是那一行的完整文字，這一格多了 `模型=建構型號` |
| `本地腦不得當審查員` | 錨點是理由句子，而句子改了——建構列換成 27B 之後，理由若還寫「9B 本地模型」就是文件說謊 |

**改任何一行原始碼之前，先 grep 一次變異登記**：登記是原始碼的下游。

## 固定負控

沒有新刀。這一格加的兩支測試（`test_建構列一定要指名型號`、
`test_建構列指名的是27B那顆`）守的是「有沒有指名」與「指名的是哪顆」，
而**既有那把 `建構列不由local打頭` 已經守著鏈的順序**——
型號只給鏈上第一家，所以順序改了型號就給錯家。三支合起來覆蓋這一格的保證。
