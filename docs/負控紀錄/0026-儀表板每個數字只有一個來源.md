# 派工儀表板的每個數字只有一個來源

## 現場

在這條線之前，儀表板的每個數字是主 agent 手拼 shell 算出來的：邏輯只活在
shell 歷史裡，沒有人能重跑、也沒有人知道某一格是「今天真的是 0」還是
「那段 shell 今天沒跑到」。這條線把它換成一條單向的路：nova 自己的讀取器 →
`src/nova/契約/儀表板.py` 一個 frozen dataclass → `src/nova/載體/儀表板/模板.html`。

儀表板最危險的失效不是壞掉，是**看起來對**。一份看起來完整的儀表板，
人會照著它做決定，而下面這四條路徑上的錯誤在畫面上跟正確長得一模一樣：

1. **算不出來的成本被畫成 0**——它看起來像個數字，而且是個好消息。
2. **契約裡沒有的格子自己長出值**（「今日合併」要 `gh` 或 fetch 才問得到，
   儀表板一律唯讀，所以契約裡沒有這一格）。
3. **重複列少一欄**——表還在、列數還對、數字都還在，只有「這是哪一家」不見了。
4. **CSS 逐字抄自設計稿，body 卻是另寫的一份**——樣式檔比對得過，
   畫面卻由一批沒有任何規則的 class 排出來，設計稿改了它們一個字都不會動。

所以五把刀分別砍契約、資料、模板的數字、模板的重複列、模板的版面語彙。
只砍前兩層的話，「模板自己補一個數字上去」與「模板自己另寫一份版面」
這兩條路徑底下是完全通的。登記在 `tests/負控/登記們/儀表板.py`，
runner 逐把套用再還原。

## 固定負控

| 破壞什麼 | 預期 |
|---|---|
| `src/nova/契約/儀表板.py` 刪掉 `算不出成本的執行數: int` 那一格 | `test_讀取器對造好的狀態目錄回出契約` 要紅：三本帳裡有一本沒回成本，少了這一格就會靜靜地變成「總共花了那兩本的錢」 |
| `src/nova/載體/儀表板/資料.py` 把 `.總成本美金 is None` 改成 `is not None` | 同一支要紅：`算不出成本的執行數` 變成有成本的那幾本，而真正沒成本的那本被當成有值加進總額 |
| `src/nova/載體/儀表板/模板.html` 的「今日合併」補上 `<span class="num">995M</span>` | `test_產出的HTML含28格未接線13格且不含假數字` 要紅：未接線的格子長出一個誰也沒算過的數字 |
| 同一個檔刪掉各家用量那一欄的 `${供應商}` | `test_原樣的模板渲染得出來` 要紅：`substitute()` 對「映射給了、模板沒用」是靜默放行的，重複列那一半要反過來檢查才擋得住 |
| 同一個檔在 `</style>` 後面塞一個 `<div class="排"></div>` | `test_模板只准用設計稿定義過的版面語彙` 要紅：`.排` 在設計稿的 CSS 裡沒有任何一條規則 |

後兩把砍的是**版面**不是數字。版面的失效沒有數字失效那麼直觀，
但它同樣是「第二份真相」：模板改了設計稿不會知道、設計稿改了模板不會知道，
而兩份都長得像「那個儀表板」，沒有人分得出哪一份是對的。

## 紅證據（測試員這一階，實作還沒跟上）

第一次審查退回之後補的四支，跑 `tests/單元/test_儀表板模板.py`：

```
FAILED tests/單元/test_儀表板模板.py::Test模板就是設計稿去殼::test_模板只准用設計稿定義過的版面語彙
AssertionError: 模板自己發明了版面語彙：排、格、標頭、階、題。設計稿的 CSS 沒有這幾條規則

FAILED tests/單元/test_儀表板模板.py::Test模板就是設計稿去殼::test_設計稿的版面結構去殼之後還在
AssertionError: 設計稿的版面結構在模板上不見了：條、活、線列、說內文

FAILED tests/單元/test_儀表板模板.py::Test模板少一格要當場炸::test_重複列少一格也要當場炸
AssertionError: 這幾格從重複列上刪掉之後照樣渲染得出來：線列.七階們、線列.名字、…、階格.階段（21 格）

FAILED tests/單元/test_儀表板模板.py::Test模板少一格要當場炸::test_整段重複列不見了也要當場炸
AssertionError: 這幾段重複列整段刪掉、資料又剛好是空的，渲染照樣成功：線列、各家列、失敗碼列、階格
```

同一次 36 支綠，其中兩支是**防擋過頭**的：原樣的模板渲染得出來、
資料是空的（沒有線在跑、沒有失敗碼）照樣渲染得出來。空表是誠實的、不是壞掉——
擋法不准嚴到把「今天 0 列」也當成「少一格」。

第四次審查（「模板不是設計稿去殼」第三次被點名）之後再補兩支，同一個檔：

```
FAILED tests/單元/test_儀表板模板.py::Test模板就是設計稿去殼::test_模板骨架與設計稿去殼逐元素相同
AssertionError: 模板的骨架跟設計稿去殼後對不上（第 1 個元素；設計稿 251 個、模板 141 個）。
  設計稿這裡是：(0, 'div', '')
  模板這裡是：  (0, 'h1', '')

FAILED tests/單元/test_儀表板模板.py::Test模板少一格要當場炸::test_模板多出未知placeholder在空資料下也要炸
AssertionError: 這幾段重複列多打一個 `${錯字}`、資料又剛好是空的，渲染照樣成功：線列、各家列、失敗碼列、階格
```

這兩支補的是前面幾支各自漏掉的一半：

* **class 名全對也可以是另一份版面。** 「只准用設計稿定義過的 class」與
  「設計稿的四個結構語彙要還在」兩關，`h1`／`h2`／`p` 排一份自己的、
  每張卡壓成一行，照樣全過。所以骨架要**逐元素**比：兩邊攤平成
  `(深度, 標籤, class)` 的序列（fixture `tests/資料/儀表板設計稿去殼.html`
  是設計稿只拿掉外殼、一個元素都沒動的那一份）。比之前只做三件票面
  允許的正規化：去殼、同形狀的連續兄弟兩邊都壓成一列、
  `.線列.列` 升級成 `<details class="說 列">` 還原回去。
* **fail-closed 不准取決於那一天有沒有資料。** 「重複列少一格要炸」是在
  渲染那一列的時候發現的；一列都不渲染就一次都不會發現。多打一個
  `${錯字}` 而資料剛好是空的——那一段連同錯字被整段拿掉，渲染成功。
  模板上有幾個變數是模板自己的事，要在讀資料之前就對完。
