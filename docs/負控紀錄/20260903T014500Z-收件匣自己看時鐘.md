# 收件匣在重置時刻之前不放行

## 固定負控

接續標記多了三格選填（`起點`／`不早於`／`額度等待`），而 `不早於` 只有在
**`_搶下來` 讀完內容、`rename` 之前**被讀，才算有牙齒：擺到 `rename` 之後，
票已經進了 `處理中/`，「沒到就不放行」實際上是「沒到也先搶走再說」。
等額度那一次的輪次不加一，改數自己的 `額度等待最多 = 6`。

| 破壞什麼 | 該紅的測試 | 親眼看到 |
|---|---|---|
| 在 `def 時候到了嗎(` 前面插一個同名前置樁一律回 `True`（不看時間，票到手就搶） | `tests/整合/test_收件匣等重置時間門.py::test_不早於還沒到收下一件就不放行到了才放行` | KILLED |
| `return 額度等待 > 額度等待最多` 換成 `>=`（界限漂一格） | `tests/整合/test_收件匣等重置時間門.py::test_第六個等待窗還在額度上限內就要排得出去` | KILLED |

兩條路壞掉的樣子都是**外表毫無異狀**：第一把刀活下來的話，`不早於` 照樣寫在票上、
欄位照樣讀得出來、`nova 狀態` 一切正常，只是下一次醒來就把票搶走、再撞一次同一個
額度、再燒一次錢——2026-09-02 那天四條線就是這個狀態。第二把刀活下來的話功能全對，
只是一天最後那個 5 小時視窗沒人等，票沒排、狀態看起來就像做完了。

錨點吊在 `def <名字>(` 那一行與那一整條 `return` 運算式上，**不吊在會被重寫的函式
本體裡的某一行**：本體被改寫時錨點該跟著搬，吊在中間那幾行只會讓刀靜靜失效。

變異登記在 `tests/負控/登記們/收件匣時間門.py`；本輪兩筆逐一手動套用、重跑指名測試，
皆為 KILLED，還原走 `cp` 備份（不是 `git checkout --`），還原後那個檔七支全綠。
