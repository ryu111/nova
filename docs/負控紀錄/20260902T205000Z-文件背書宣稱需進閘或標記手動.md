# 文件背書宣稱需進閘或標記手動

## 現場

設計文件若宣稱由掛了 `@pytest.mark.真cli` 或 `@pytest.mark.真端點` 的測試背書或釘住，因兩測試閘預設皆排除此類標記，測試實際上不會在自動閘被執行。
`tests/驗收/test_文件即事實.py` 檢查文件宣稱之背書測試時，必須確保該測試存在於自動閘的收集清單中；若為未進閘的手動測試，宣稱處必須明確標記 `手動跑`，否則閘必須擋下。

## 固定負控

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| 在文件宣稱由掛 `真端點` 的測試背書且未標記手動跑（如 `本機推論由 \`test_真端點列得出模型清單\` 背書。`） | `test_未進閘真端點測試未標記手動時抓出` 或 `test_文件宣稱的測試要在閘收集或明示手動` 要紅 | 紅：`AssertionError: assert [] == ['test_真端點列得出模型清單']` |
| `docs/設計/02-統一LLM介面.md` 將 `（手動跑）` 拿掉，直接宣稱由 `test_可編輯真的上得了網` 背書 | `test_文件宣稱的測試要在閘收集或明示手動` 要紅 | 紅：抓出未進閘且未標記手動跑之宣稱 |
