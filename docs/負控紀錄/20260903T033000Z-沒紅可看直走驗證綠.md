# 沒紅可看在非首輪是一條邊，不是一種收場

## 固定負控

`no-red-to-see` 原本一律收 4。實測今晚兩條線（230246、9c0d04）都是「審查退回只要改測試」：
src 早就在了、測試本來就綠，根本沒有紅要驗，卻照樣收 4，要人或脫圈腳本再接一次
`--起點 verify-green` 才走得完。

現在「是不是首輪」是**一個述詞、兩個消費者**：`_是首輪(軌跡, 接續來的=…)`
（起點是 `測試`、`任務.前情` 是空字串、軌跡上沒有實作步、也沒有要求修改的審查步）。
`_改道去哪` 拿它決定「非首輪連綠達門檻 → 直走 `驗證綠`」，
`卡住了` 拿它決定「只有首輪才回 `沒有紅可看的理由`」。
**首輪連綠仍然收 4**——那是測試員沒寫出紅，直走 `驗證綠` 等於跳過 TDD 的第一步。

兩個消費者會漂掉，而且漂掉的每一種長相都很像做完了，所以每把刀各守一邊：

變異登記在 `tests/負控/登記們/沒紅可看直走驗證綠.py`（一線一檔）。
第四把是這一輪補的：它是今晚 230246／9c0d04 那兩條線唯一的長相——
**沒有任何接續訊號可以借**，「不是首輪」全靠 `_實作跑過了`。
手動套上那個變異時，只有新增的那一支紅，其他七個相關節點全綠，
證明這半條保證原本沒有人守；看完紅已逐字還原（`狀態機.py` 的 sha256 前綴回到 `6251467430f1`）。

第五把守的是 `_實作跑過了` 裡「要求修改的審查步也算」那個分支本身。
原本只有帶實作步的軌跡被鎖住，把那個分支拿掉六個相關案例仍全過；
補上「只有要求修改審查步、無實作、非接續」那條軌跡的單元測試之後，
runner 實跑這一把是 KILLED，變異存活的路已經封掉。

`tests/負控/登記們/沒有紅可看.py` 第一把刀的錨點同步換成帶首輪判斷的那兩行，
守的仍然是「首輪連綠會收 4」；第二把（`連綠次數 = …` 那行）不受影響，沒動。
