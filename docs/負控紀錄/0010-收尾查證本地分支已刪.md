# `gh pr merge --delete-branch` 回 0 不等於本地分支真的被刪掉

## 現場

`nova 收` 的收尾把 `gh pr merge --squash --delete-branch` 的退出碼當成
「分支已刪」的證據。**那是別人的回報，不是現場的事實。**

實際踩過：本地分支被工作樹佔用時，`gh` 會印

```
failed to delete local branch <分支>: cannot delete branch '<分支>'
used by worktree at '<路徑>'
```

**而整個指令仍然回 0**（遠端那半成功了）。於是收尾宣告完成，
本地分支留著、工作樹留著，下一輪 `nova 線` 還會看到它。

這正是 CLAUDE.md 判準第 3 條的形狀：**墊片證明的是轉遞形狀，不是可達性。**
`gh` 回 0 證明的是「指令跑完了」，不是「分支不在了」。

## 改法

`src/nova/載體/命令/收.py:91` 合併之後**回到現場查一次**：

```python
return _查證本地分支已刪(根, 頭分支)
```

查不到就回非零並**指名是哪一條分支**——不要只說「收尾失敗」。

**破壞**：拿掉查證，直接宣告成功——

    return 0  # 破壞：不查證就宣告成功
```

**該紅**：`tests/整合/test_收尾合併後查證.py`

```
1 failed in 0.86s

**為什麼這一刀砍在這裡**：`return 0` 是「相信別人的回報」這個錯誤形狀的最小實例。
它跟原本的 bug 一模一樣——差別只在原本是 `gh` 說 0，破壞版是我們自己說 0。
