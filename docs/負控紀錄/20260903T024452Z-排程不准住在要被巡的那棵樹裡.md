# 排程的工作目錄不准落在要被巡的那棵樹裡

## 固定負控

`排程設定` 印出來的 `WorkingDirectory` 從「主工作區」改成 daemon 那份 checkout，
守門的那一格是「工作目錄等於 `專案` 或在它底下就當場炸、一個字都不准印」。

| 破壞什麼 | 該紅的測試 | 親眼看到 |
|---|---|---|
| 在 `def 排程設定(` 前面插一個同名前置樁，把 `專案` 換成 `/nova負控/不存在的專案`（守門那格的比較永遠不成立） | `tests/單元/test_排程不准住主工作區.py::test_工作目錄在專案底下就raise` | KILLED（`DID NOT RAISE ValueError`） |

這一格壞掉的樣子是**外表毫無異狀**：plist 印得出來、`launchctl load` 收得下去、
排程也真的會醒，只是它站在主工作區裡。等到那棵樹壞掉（rebase 到一半、conflict
沒收、被 `git clean` 掃過）的那一天，排程跟著一起壞——而那正是最需要它還活著的
時刻（收件匣 daemon 跑在主工作區把人鎖在門外過）。守門那格拿掉不會讓別的測試變色，
`WorkingDirectory` 仍然是一個合法字串，所以要釘一支具名測試。

錨點吊在 `def 排程設定(` 那一行，**不吊在函式本體裡會被重寫的某一行**：本體改寫時
錨點該跟著搬，吊在中間那幾行只會讓刀靜靜失效。

變異登記在**新檔** `tests/負控/登記們/排程落點.py`（一線一檔，沒有動
`tests/負控/登記.py` 與別票的 `登記們/*.py`），`最多秒 = 120`。本輪手動套用一次、
重跑指名測試看到紅，還原走 `cp` 備份（不是 `git checkout --`），還原後那個檔全綠；
runner（`test_登記的變異會被殺[排程設定看不見真的專案等於工作目錄不設防]`）也跑過一次，KILLED。
