# 重構員說「無需重構」而且工作區雜湊沒變，才跳過 verify-refactor

## 固定負控

守的是「跳過一次驗證」的三半保證：判準要有結構證據、證據要真的拿到手上、
兩條生產路徑都要記得下來。登記在 `tests/負控/登記們/跳過驗證重構.py`。

| 破壞什麼 | 預期被哪裡抓到 |
|---|---|
| 拿掉判準裡的雜湊比對（`該跳過驗證重構` 只看「無需重構」那句話） | `tests/單元/test_跳過驗證重構.py::test_無需重構且雜湊沒變才跳過[說無需重構但樹動過了]` |
| 重構步不 append 工作區雜湊（改回 `None`） | `tests/單元/test_跳過驗證重構.py::test_跳過那一輪判準沒被叫到而且軌跡沒有verify_refactor` |
| `命令列.py` 的接線點不傳 `記跳過=建記跳過(帳)` | `tests/整合/test_跳過驗證重構有接線.py::test_兩個接線點都把記跳過傳進跑工作流[命令列]` |

## 實測

2026-09-02（UTC）跑固定負控 runner，三筆變異全部被殺（`3 passed`）：

- **只看字串不看雜湊**：`src/nova/迴圈/狀態機.py` 的
  `and 重構後雜湊 is not None and 重構後雜湊 == 已驗綠雜湊` 換成 `and True` 之後，
  「說無需重構但樹動過了」那一格**紅**——判準對兩棵不同的樹都說可以跳，
  跳過就變成模型自己宣布的停止條件（CLAUDE.md 硬規則第 2 條）。
  另外兩格（樹沒動過該跳、沒說無需重構不該跳）仍綠：它們只碰得到字串那一半，
  **不會互相掩護**，所以這一刀點的正是雜湊那一半。
- **重構步不記工作區雜湊**：`src/nova/迴圈/工作流.py` 的 append 改回
  `_工作區雜湊(…) if 定義.種類 is 種類.判準 else None` 之後，迴圈那一支**紅**——
  重構後的雜湊永遠是 `None`，判準拿不到證據就永遠不跳，`驗證重構` 照跑，
  軌跡上多一步、假判準多被叫一次。
  這一刀點不動純函式那三格（雜湊是字面值餵進去的，一行 `工作流.py` 都走不到），
  登記裡只寫迴圈那一支。
- **命令列少接一行**：刪掉 `記跳過=建記跳過(帳),` 之後，整合測試的「命令列」那一格
  **紅**——`跑工作流` 收到 `記跳過=None`，真線（排程、`nova 跑`、`nova 派工`
  最後都走命令列）上的跳過會靜靜地沒有帳，而「這輪沒跳過」跟「跳了但沒記」
  在帳本上長得一模一樣。「門面」那一格照舊綠，證明兩個接線點是兩把刀。

三刀都由 runner 自動改回原狀，改回來之後三支測試全綠。
