# 派工前看額度與狀態列額度進快取

## 現場

2026-09-02 15:16～15:28 台北派出四條線，15:29 四條在同一分鐘內全撞 claude 的
session limit（`resets 4:40pm (Asia/Taipei)`），$3.75、41 分鐘模型時間換回四棵改到一半的
工作樹。那天的 `nova 派工` 過了 `_派工該擋的理由` 就直接落票、開樹、起線——
**沒有任何一格讀過額度**。

補上兩件事：

- `命令列._額度先擋一下`：落票開樹之前只讀快取（`只讀快取的額度()`，不 fork），
  任一家任一視窗用掉 `額度門檻百分比`（90）以上就回護欄碼 4，票不落、樹不開、模型不叫；
  查不到（快取沒這家／那一家自己的時戳超過 `額度數字最舊秒`）照派，但要說出口。
- claude 的數字從哪來：CLI 沒有 usage／quota 子命令，唯一來源是狀態列 JSON 的
  `rate_limits`，所以走 `nova 額度 --從狀態列` 從 stdin 收。

而這條路真正的地雷在**寫入端**：快取本來是「一次覆寫整份 `families`、只有一個全域 `ts`」。
`nova 額度` 拿 cx／ay 兩家的清單覆寫，狀態列剛寫進去的 `cl` 就消失了；
反過來只寫 `cl` 卻更新全域 `ts`，cx／ay 的舊數字會看起來也是剛查的。
所以兩個寫入端改成共用 `載體/額度._合併寫入`：只換點名的那幾家、各家蓋各家的 `ts`、
全域 `ts` 只在去問過人的那條路更新。

## 固定負控

三把刀登記在 `tests/負控/登記們/派工前看額度.py`（一線一檔），下面是**親手下刀**
看到的實際輸出。

| 破壞什麼 | 預期 | 實際 |
|---|---|---|
| `載體/命令列.py` `額度門檻百分比 = 90` → `= 101`（門在，但永遠不擋＝`_額度先擋一下` 一律回 `None`） | `test_額度快撞到就不派而查不到就放行且都要說出口` 要紅 | 紅：`AssertionError: 額度剩不到一成還照派。stdout=派出去了。線名：…f3b0dc / 工作樹：…/nova-wt-… assert 0 == 4`（runner 判 KILLED） |
| 把 `載體/額度.py` `查詢額度` 的寫檔改回 `_寫入快取檔(成功家族清單, ts=現在秒)`（＝一般查詢覆寫整份快取） | `test_兩個寫入端都保留別家_cl帶自己的ts_全域ts不動` 要紅 | 紅：`AssertionError: 快取裡的 cl 應恰好一格，實際 0 格：{'ts': …, 'families': [{'family': 'cx', …}, {'family': 'ay', …}]}`（runner 判 KILLED） |
| `載體/額度.py` `狀態列節流秒 = 60` → `= 0`（狀態列每次工具呼叫都重寫快取） | `test_六十秒內再餵不重寫_沒rate_limits不寫_百分比四捨五入` 要紅 | 紅：`AssertionError: 六十秒內又寫了一次；狀態列一分鐘叫幾十次，這是幾十次磁碟寫入`（第二次餵的 88% 蓋掉了第一次的 41%，runner 判 KILLED） |

三種壞法的共同點是**外表毫無異狀**：門檻拉高之後 `nova 派工` 照樣回 0、照樣開樹；
覆寫整份快取之後快取檔還在、cx／ay 還是新的，只有 `cl` 靜靜地不見了（而那道門
讀不到 `cl` 就放行，於是第一種壞法自動成立）；節流歸零則是功能全對，只是一分鐘
多寫幾十次檔。三件事都不會讓別的測試變色，所以各釘一支具名測試。

第一、三把的錨點打在模組層常數上，不是打在 `_額度先擋一下` 的函式體裡：負控要求
「該紅的測試走得到被破壞的那一行」，而 coverage 只看得到父行程，那兩支測試走的是
真的 `nova` 子程序（`--從狀態列` 的「回 0、什麼都不印」與派工的「票不落、樹不開」
只有從子程序外面看得到）。代價說清楚：這兩把刀證明的是「這個常數說了算」，
不是「那一行被走到」。

錨點跟著實作走：`查詢額度` 那一行呼叫 `_合併寫入`、兩個常數的字面值。實作換寫法時
錨點對不上會是 `RUN_ERROR`，不是靜默通過。
