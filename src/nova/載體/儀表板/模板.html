工作做完會回報一個數字，告訴你「怎麼結束的」（來源：--json 的 exit_codes）：
  • 0 成功——做完了，沒問題。
  • 1 失敗——確定沒做成。
  • 3 不知道——電話斷了，不知道他做完沒。像你叫人去買牛奶，講到一半斷線——你不能再叫一次，不然可能買回來兩瓶。所以這個數字的規矩是「不准重來」。

這一區的四個數字要一起讀
登記檔數與紀錄檔數是真的數得出來的；「幾把刀」要 import tests、src 不准， 所以那一格喊未接線；第三格與第四格的分子也沒有資料欄，一樣未接線。 閘綠而負控缺：分母數得出來、分子沒有—— 所以這一頁只給分母。來源：--json 的 mutation
「負控」是這樣一件事：你怎麼知道保全系統真的有在運作？故意去弄壞一次，看警報會不會響。
  • 幾把刀——要 import tests 才數得出來，src 不准，所以這一格未接線。
  • 幾份紀錄——寫在紙上給人看的，電腦不會自己重做。
  • 幾條閘在檢查——閘規則沒有「這條守的是負控」這個欄位，分子答不出來。
  • 幾階被指派——連「誰該去做」都還沒落成欄位。
分子未接線、分母數得出來——這兩件事在畫面上要分得開。
